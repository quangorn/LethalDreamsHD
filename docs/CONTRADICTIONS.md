# CONTRADICTIONS.md — противоречия в материалах (фиксировать, не «починить» молча)

1. **Magic .pyc: base vs modern.** pyd-материалы говорят: magic 13 (1995 Delphi)
   — «base»; наши инструменты (`tools/pyc/py22_worker.py`, `pycbuild.py`) печатают magic 10
   (`ed2d0d0a`, Python 2.2.3). Установленная игра содержит оба: `ui/ui.pyc` (base,
   magic 13, md5 `57744e6f…`) и `ui/types.pyc` (modern, magic 10). docstring
   `tools/pyc/install_patch.py` («magic ed2d0d0a») описывает modern-печать; для
   base-модулей он не применим (манифест хранит оба md5-канона). Противоречие
   разрешено манифестом, терминология: `docs/KNOWLEDGE.md`.
2. **pycbuild.py header mtime.** Истори­ческий `pycbuild.py` ставил source mtime
   `1078421172` — «base-компиляция». `tools/pyc/py22_worker.py` ставит build-time. base-печать
   воспроизводится только с явным манифестным mtime (`apply_patch.py`). Не совпадение
   md5 при «просто собрать» — не поломка, а свойство этих двух инструментов.
3. **build_pyc.py vs pyd.** `build_pyc.py` (утрачен: покрытия нет ни в git, ни в приватных архивах сессий Project/1-3.7z, 5.7z, 6.7z, 7.7z, original.7z, hd_pack.7z, python_libs.7z) (утрачен, покрытия нет) использовал pyd, давая magic 13;
   `pycbuild.py` (2.2.3) — magic 10. Документы сессий это смешивали.
4. **black_btf.py «для всех 1349»** — sidecar-черные .btf существуют только как
   архивные black-пары (snapshot-архив, 16+), в установке их нет; `white.btf`
   удалён при установке HD Pack (после создания black-пар). Фраза скрипта историческая.
5. **cursor.pyc.** Установленный файл (md5 `4a8eb4bab413…`) ≠ base-печать
   published-патча (`60754a253515…`): в установке курсорный патч версии 6 с другим
   mtime и телом. Число `644b54d8…`, встречавшееся в ранних заметках как «base-печать»,

6. **install .btf = 1342** — план писал «1268+измерения»; факт измерен: 1342

## Перепроверка 2026-11-15 (день): HANDOFF опровергнут, найдена реальная линия текста
- `[P]` **Раскладка GL-вершины не та, что в HANDOFF.** Реальная запись (stride 0x20):
  `+0 float x`, `+4 float y`, `+8 float z` (= -1), `+0xc` цвет RGBA (4 байта),
  `+0x10 float u`, `+0x14 float v`, `+0x18..0x1f` padding. Доказано: дампом
  (`tools/archive/frida_probe/ld_ver1.py`) и дизасемблом `FUN_004708d0` (glVertexPointer(3,FLOAT,0x20,V);
  glColorPointer(4,UNSIGNED_BYTE,0x20,V+0xc); glTexCoordPointer(2,FLOAT,0x20,V+0x10);
  glDrawElements). Логгер `tools/archive/frida_probe/ld_phases2.py` читал базу `esi+0xc+idx*32`, а вершина
  начинается с `esi-0x10` → сдвиг 0x1c: он видел padding + СЛЕДУЮЩУЮ запись
  (x,y,z,color,u,v). Отсюда весь «layout u,v,w,x,y» и все «сигнатуры 538/417» в
  HANDOFF — это на самом деле экранные x/y соседней вершины. Cave `exepatch6`
  масштабировал поля +0xc/+0x10 от `esi` = padding и x следующей записи → «тождество»
  и «ноль эффекта» объясняются ошибкой адресации, а не отсутствием рычага.
Рабочий маршрут статического патча — `docs/PATCHES.md`, разделы exepatch8/9/10/12.

12. **«Движок НЕ грузит `.tex`-записи с изменённым w/h» — опровергнуто (17.11.2026, вечер).** Ранняя запись

    `docs/archive/ISSUE_tex_upscale.md` («РЕШЕНИЕ»), `docs/OBSERVATIONS_TEXTURE.md`
    («Разбор чтения `.tex` движком и TLV-размеры записей»).
13. **«Шапка записи = 40 байт»** — неточно: `name_len` u32 лежит в gap'е перед именем, поля шапки
    занимают 26 байт (`hdr_off = name_off + name_len`), а перед ними внешний TLV-заголовок записи
    (type по `name_off-32`, size по `name_off-28`). Формулировка ранней scan-схемы; уточнение —
    `docs/OBSERVATIONS_TEXTURE.md` (раздел 2026-11-17, вечер).
14. **«B23 `0x44c0b0`: равно/unordered → B31» — неверно.** `TEST AH,0x41; JP` берётся при
    **строго большем** и unordered (`phase > [unit+0xfc]`); меньше и равно (упорядоченное ≤) идут
    в fall B24. Та же ошибка — `battle_ai_disasm4.md` R4/B23 и строка «state≠3+float==».
15. **«IAT `0x4ec064` = LoadCursorFromFileA» — неверно.** `objdump -p` установочного EXE:
    `000ec064` = `OutputDebugStringA` (ordinal 0x268), `LoadCursorFromFileA` — `0x4ec264`.
    Сайт `0x44c1c0` пишет debug-строку; реализация — `native::output_debug_string_a`.
16. **«`[ESP+0x160]` в R7/R16 — param_2, „clobbers bit3"» — неверно.** В блоке с `ADD EBP,0x18`
    ESP = frame−0xc, поэтому `0x160(%esp)` = **`frame+0x154`** (SEH trylevel), а не param_2
    (`frame+0x160`). param_2 пишется только B4 (`orl $8`) и читается на B80 (`0x44cb07`).
17. **«Sentinel B102 = −9990.0f» — неверно.** Байты `0xc61c4000` = **−10000.0f**
    (−9990.0f = `0xc61c1800`). Ошибка в `battle_ai_disasm4.md` (R16) и `battle_ai_disasm6_structure.md`;
    значение уходит в per-tick запись `45eee0` — R17 читать из листинга/R16, не из старых карт.
18. **«`45c6f0`: guard `CMP EAX,ECX` = сравнение с `this`» — неверно.** Перед сравнением стоит
    `XOR ECX,ECX` (`0x45c6f2`), т.е. условие нулевой ветви — `ctx == 0`; `ctx == this` не встречается
    (0 вызовов в 8 захватах). Вывод был сделан по сниппету без этой инструкции — цитировать тело
    `45c6f0` только строкой от `0x45c6f0` до `RET`, целиком.
