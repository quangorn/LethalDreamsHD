### Мигание окна при смене фокуса и ловушка `WS_EX_COMPOSITED`

**Симптом:** экран мигает при alt-tab и при смене фокуса; попытка лечить через `WS_EX_COMPOSITED` ломает запуск игры.
**Причина:** видео wndproc `FUN_0049a4f0` на `WM_LBUTTONUP (0x202)`, `WM_RBUTTONUP (0x204)`, `WM_LBUTTONDBLCLK (0x205)` делает `ShowWindow(DAT_0051d5e8, 0)` = SW_HIDE (fileoff 632177, байты `6A 00 50 FF 15 1C`); `WS_EX_COMPOSITED` неприменим: оба класса окон имеют `CS_OWNDC` (обязателен для wgl), по MSDN он не работает с `CS_OWNDC/CS_CLASSDC`, живой P/Invoke-тест `CreateWindowExA(0x20040000,...)` → NULL, `GetLastError=87`, exstyle-патч (`push 0x40000` → `push 0x20040000`) ломает запуск EXE.
**Обход:** однобайтовый патч SW_HIDE→SW_SHOWNORMAL на fileoff 632177 (в baseline `45e93d46…`, `tools/exe/apply_baseline.py`) + borderless-патчи `tools/exe/exepatch3.py` (`CDS_FULLSCREEN→CDS_TEST`, `NULL_BRUSH`, снятие рамок); `WS_EX_COMPOSITED` не применять. Полный набор правок — `docs/PATCHES.md`, раздел Borderless.

## Итерация 2026-11-15 (вечер): фильтр/гейт на сайте 0x470932 — отрицательные результаты и разгадка

**Симптом:** «положительные» эффекты масштаба на сайте draw, зарегистрированные в прошлой итерации, при точном дизасембле оказались тождеством; все правки полей пула — ноль эффекта.
**Причина:** полный «рабочий» статический cave (exepatch6, PARTS full) математически = тождество (`x' = 0.75·x + 0.25·center = x`); «сжатие 538→300» было артефактом состояния меню (hover/no-hover); запись в поля записей пула (`u,v`, `x,y`, `w`, flags) не меняет рендер — geometry glyph-квадов загружается один раз и при draw из пула не читается.
**Обход:** задача «уменьшить шрифт при 4K правкой сайта draw» закрыта как бесперспективная; рычаг — путь текста `0x477220`/`FUN_0041d020` (расцепить UV и advance) — реализовано пещерой на назначении шрифта: `docs/PATCHES.md` (exepatch8/9/10/12). Снимки делать только при активном окне (`shot_activate.ps1`).
подробный разбор — docs/archive/NARRATIVE_2026-11.md («Итерация 2026-11-15 (вечер): фильтр/гейт на сайте 0x470932 — отрицательные результаты и разгадка»)

### Ловушки съёмки и Frida (перепроверка 2026-11-15)

**Симптом:** снимки дают байт-в-байт одинаковые PNG / «нулевые эффекты»; скрипты молча падают на каждом вызове.
- **Окно не перерисовывается, пока не в foreground:** снимки после ухода курсора за окно давали байт-в-байт одинаковые PNG — все «нулевые эффекты» на таких снимках недостоверны. **Обход:** активировать окно (`ShowWindow(SW_RESTORE)+SetWindowPos(TOPMOST)+SetForegroundWindow`) и снимать экран при активном окне — `tools/archive/probes/shot_activate.ps1`; Frida-сессию закрывать до снимка.
- **Frida 17: нет `Memory.writeByteArray`/`readByteArray`** — только `ptr.writeByteArray()`/`ptr.readByteArray()`; скрипты, использовавшие Memory.*, молча падали на каждом вызове.
- **Откат вершин в `onLeave` бесполезен/вреден:** драйвер читает client-arrays ПОЗЖЕ возврата из submit-функции (сдвиг x +300 без отката двигает весь текст, с восстановлением в onLeave — ноль). **Обход:** не восстанавливать — буфер пересобирается каждый кадр.

## Апскейл альфы (маски) — попробовали, не пошло (2026-11-15, ночь)

**Симптом:** GAN-апскейл маски даёт DC-подъём фона, раздутую массу штриха и размытый силуэт.
**Причина:** маска — уже гладкая карта покрытия (сплошные формы, а не контур); новой информации в ней нет, верная реконструкция = честная интерполяция (Lanczos), а GAN только добавляет DC-подъём вуали на всю текстуру и раздувает массу штриха.
**Обход:** альфа остаётся как есть; RGB — remacri; установленные 4x-листы (RGBA remacri) уже оптимальны по альфе — переустановка не нужна.

## Черезстрочные PNG: квадратная dims-амбигуность (2026-11-15, вечер)

**Симптом:** часть текстур криво сконвертировалась в PNG — черезстрочные паттерны (`mm_ng_tt_transmuter`, `mm_tt_save`, `msg_btm_alt`, `fire01`, `ship_deck01`).
**Причина:** поле имени имеет длину не кратную 4, поля после имени идут со сдвигом; `parse_btf`, сканирующий пары по 4-выравненным офсетам и предпочитающий квадратную пару, для `w != h` берёт ложную квадрату (blob 262144 подходит и как 512x128, и как 256x256); пакер пропатчил не w,h, а поле `w*h`/`blob_len` — движок читает первые `w*h*bpp` байт = верхнюю полосу кривого апскейла.
**Обход:** канонические dims = первые два u32 после поля имени (`tools/btf/unpack_btf.py`, `canon_dims()`); пакер `pack_btf.pack_one` патчит w,h по каноническим офсетам; round-trip md5 побайтово совпадает для всех 5 затронутых файлов.
подробный разбор — docs/archive/NARRATIVE_2026-11.md («Черезстрочные PNG: квадратная dims-амбигуность (2026-11-15, вечер)»)

### Q-режим «квадратный диалог по центру» — модель оказалась неверной (16.11.2026)

**Симптом:** экраны R/E/F1 выходили меньше 4:3-эталона, клики по кнопкам этих экранов срабатывали не там.
**Причина:** модель «1024x1024 → экранный квадрат со стороной h» неверна: видимая композиция этих экранов — канвас 1024x768; Q отображал весь квадрат масштаб `q = h/w = 0.5625` вместо канвасного `h/768`; прямоугольники шли q-трансформом (`ECQ/EYQ`), а хит-тест/курсор — k-схемой.
**Обход:** Q-режим отменён, код и Q-листы удалены; квадратные диалоги получают обычную k-схему (`DIALOG_TEX` в `patches/hd_scale.py`). Хроника и план — `docs/archive/CANCELLED_Q_MODE.md`; финальная реализация — `docs/PATCHES.md`, раздел «R/E/F1: финальное решение».

## Обязательные грабли проекта (симптом → причина → обход)

- **Интерактивный `7z` без `-y` при распаковке baseline** — стенд зависает на запросе перезаписи. Причина: архив содержит уже извлечённые файлы; `7z` ждёт ответа. Обход: флаги `-y` и `stdin=devnull` в `tools/exe/apply_baseline.py` (исправлено коммитом `a06d5d5`).
- **`sys.path.insert(0,'C:/...')` в Cygwin Python 3.12** — модуль не находится (`ModuleNotFoundError`). Причина: cygwin-python не понимает windows-буквенные пути. Обход: `/cygdrive/c/...` (см. грабля выше).
- **PowerShell-скрипты не запускаются** — политика выполнения блокирует `.ps1`. Обход: `powershell -NoProfile -ExecutionPolicy Bypass -File <script>`.
- **Игровая установка read-only для инструментов**: любая запись в игру — только явным `--install` проверенных скриптов (`tools/pyc/install_patch.py`, `tools/exe/* --install`, `tools/fonts/gen_font4x.py --install`). Обход экспериментов: scratch-дерево (`LD_CONFIG` с другим `game.root`) + снапшот md5+mtime до/после, diff обязан быть нулевым.
- **`gate` перезаписывает `build/*.py` и меняет их mtime** (контент идемпотентен). Следствие: mtime исходника попадает в header `.pyc`, значит md5 «просто собранного» .pyc не совпадает с base-печатью манифеста. Обход: base-печать собирается только с явным `pyc_source_mtime` (`tools/apply_patch.py` переписывает `bytes[4:8]`); зафиксировано в `docs/PATCHES.md`, `docs/VERIFY.md`.
- **PYTHONPATH worker'а = py223 + `cache/lib`** (игровой `Lib` не входит; кэш наполняет `python3 tools/extract_pristine.py lib`). Неправильный PYTHONPATH → воркер падает `ImportError: No module named os` (зафиксировано в записи установки боевого HUD).
- **Заголовок `.pyc` = magic `2ded0d0a` + mtime исходника** → md5 зависит от mtime. Обход: рецепт base-печати (`docs/PATCHES.md`, «Рецепт .pyc»); `--quick` при drift'е печатает разбор header/body.
- **`co_filename` = путь репозитория**: тело bytecode совпадает с base-печатью только при компиляции из канонического пути `patches/<module>.py`; в зеркале/scratch-дереве md5 легитимно расходится (checker печатает пояснение). Обход: компилировать только из канонического пути.
- **8 архивных скриптов не парсятся Python 3** (py2-only `print`, незакрытые `***`-строки): они написаны для 2.2.3/2.x. Обход: запускать тем интерпретатором, которому они принадлежат, или читать как документацию; список — `tools/archive/README.md`, абзац «8 архивных скриптов не парсятся Python 3» (8 имён: 4 `disasm/disdiff*.py`, 3 `decompile/*`, `tmp_scratch/bm_patch_backup.py`).
- **Чёрный фон** — включение black-сайдкаров требовало файла `blackbg.flag` в корне игры;
- **`mm_bkg01.btf` в игре побитово равен hd_pack `mm_bkg01_169.btf`**: ярус assets сверяет .btf по правилу манифеста, и «родной» фон меню в установке — это HD Pack-запись. Обход: оригинальный фон искать в archive.pristine, не в установке.
- **Строгий `--quick` падает на любом дрейфе code tier** (так было с `ui/cursor.pyc` v6 до 19.11.2026; `--full` показывал KNOWN, rc 0). Обход: привести файл к base-печати манифеста (`apply_patch.py <м>` + `install_patch.py <м> --install`), вручную md5 не править.
- **`data/video/*.wmv` удалены из установки намеренно** (allowlist, glob `data/video/*.wmv`); отсутствие `boolat.wmv`, `russobit_r.wmv` разрешено. Обход: не добавлять их в проверку как MISSING.
- **Игра не запускается с родной альфа-`python22.dll` и без `Lib/` и корневых `.pyc`** — финальный код-слой импортирует stdlib, финальный 2.2.3 требует `site.py`/`codecs.py` при `Py_Initialize`, альфа 2.2a4+ их не имеет. Обход: Python-слой — обязательная часть базы (`python22.dll` 2.2.3 + `Lib/` 713 файла + 11 корневых `.pyc`); восстановление — snapshot-архив или приватный `python_libs.7z` (725 файлов, crc-сверка с установкой). Замеры — `docs/OBSERVATIONS_ENGINE.md`, раздел «Python-слой».
- **`Lib/*.pyc` «устаревшие» для движка** (header-mtime ≠ mtime `.py`) — движок проверяет staleness по header-mtime → при импорте перекомпилирует, md5 «просто собранного» .pyc не совпадает ни с чем в манифесте. Обход: после сборки выставлять `bytes[4:8]` = mtime исходника (рецепт `.pyc` — `docs/PATCHES.md`); `--quick` печатает разбор header/body.
- **«`site.py` удалён» из документации сбивает с толку**: удалены только подложенные копии в **корне** игры; `Lib/site.py` (10720 B) и `Lib/codecs.py` (20167 B) в установке есть. Обход: читать `Lib/`, а не искать `site.py` в корне; историческая пометка «файл удалён» относится к корневым копиям (`site.py`/`codecs.py` лежат в `Lib/`).

### Рамка `WS_BORDER` вместо `h+1` — мигание уходит, но способ непригоден (16.11.2026)

**Симптом:** borderless `3840x2160` (окно ровно = экран) даёт OSD монитора и мигание на запуске/alt-tab/выходе.
**Причина:** `WS_BORDER` (один байт, fileoff 149932, `push 0x80000000` → `push 0x80800000`) убирает мигание, но движок хранит `w,h` из аргумента `SetDisplayMode` (3840x2160), а реальная поверхность `3838x2158` — краевые зоны курсора уходят за drawable и детект краевой прокрутки рвётся; рамка в 1 px видна → вариант отклонён.
**Обход:** `h+1` по высоте (`sw==w and sh==h` в `gamescript.Initialize`) — единственный подтверждённый вариант на 4K; `WS_BORDER` и отключение MPO не применять.

### Пещера в `.rdata` для 4:3 роликов — игра падает, путь закрыт (16.11.2026)

**Симптом:** после применения патча игра не запускается/падает через несколько секунд.
**Причина:** падение (`0xc0000005`, faulting address вне образа) воспроизводится и на identity-пещере, и на пещере, пропускающей вызов — дело не в числах 4:3, а в механике site-jmp + пещеры вне `.text`; свободного места в `.text` нет (zero-run'ов >=16 B ноль).
**Обход:** ролики править site-jmp-пещерой вне `.text` нельзя. EXE возвращён на baseline `171319bbc170…` (`--restore`), игра запускается. Ролики не растянуты: рендерер сам letterbox-ит `640x480` в 4:3 по центру (замер снимка — `docs/OBSERVATIONS_ENGINE.md`, «Ролики уже рендерятся 4:3»).

## Импорт 2.2.3 чувствителен к регистру имени модуля (плоский дамп установщика не импортируется)

**Симптом:** в дереве интерпретатора из плоского дампа `Python-2.2.3.exe` startup даёт `'import site' failed`, а `import site`/`os`/`string`/`UserDict` падает `ImportError: No module named …`; worker'у не хватает stdlib.
**Причина:** в 2.2.3 `case_ok` (реализация MS_WIN32) сравнивает точное имя файла на диске с именем модуля; файлы дампа (`STRING.PY`, `SITE.PY`, `USERDICT.PY`) не совпадают → импорт не находится, хотя read-путь работает; при env var `PYTHONCASEOK` импорт проходит. ## Пересборка `.tex`-записи в `.map`: два грабля, дававшие краш (2026-11-17, вечер)

- **Лишний `name_len` u32-префикс при пересборке записи** — родной `name_len` u32 лежит в gap'е перед именем; `rec_bin = pack('<I', name_len) + name + hdr + blob` сдвигает поля на +4: short-проверка разбора (`FUN_00495300`, младший байт обязан быть 0) читает мусор, FACT (`FUN_00495720`) возвращает NULL, снимание NULL на `0x467f54` → `0xC0000005`. - **TLV-размеры наружных заголовков обязаны расти вместе с blob'ом** — payload ходит ADV (`FUN_0049bf70`) по цепочке заголовков `(type u32, size u32)`; размер внешнего заголовка записи (u32 по `name_off-28`) и каждой накрывающей секции равняются длине содержимого; при старом размере ADV сбивает координаты потока → FACT NULL → краш (`0x467566`). Правка — `tools/tex/patch_map_pattern.py` (`chain_headers` + `fix_chain`); дельта прибавляется (+ апскейл, − даунскейл).
- **Живой прогон игры переписывает базовые шрифты установки родным содержимым** — при выходе движка `data/fonts/ld_{numbers15,tahoma11,uncial12,uncial20}.{fdf,btf}` получают native-размеры вместо HD-набора `config[assets.hd_pack]`; симптом: `--full` печатает 7 `DRIFT hd_pack … size != …`. Обход: восстановление 8 файлов из `<hd_pack>` (`7z x -y -o<game.root> <hd_pack> data/fonts/… data/textures/…`), сайдкары `*_169/*_43` не трогаются; после восстановления `--full` rc 0.

## x87-маска `0x41` + `JP` = «больше или unordered» (21.11.2026)

- **Симптом:** ревью дважды переворачивает гейт `TEST AH,0x41; JP` (B13/B23 `44bdd0`) и
  объявляет порт инвертированным. **Причина:** PF — чётность `AH & 0x41`, а не «нулевой результат»:
  `a>b` → `0x00` (PF=1, **JP взят**), `a<b` → `0x01` (PF=0), `a==b` → `0x40` (PF=0),
  NaN → `0x45 & 0x41 = 0x41` (чётно, **взят**). **Обход:** `b0_gate_41_jp = !(a<=b)`,
  `b0_gate_41_jnp = a<=b`, `b0_gate_41_jnz = !(a>b)`; проверка — `re/x87_flags6.exe`.

## `446a80` (`ret 0x3c`) снимает `sub 0x3c` — join ESP = frame (21.11.2026)

- **Причина:** захваты v12..v15 несут только указатель сетки (`bdd0_in.tree`); арена материализует под
  него нулевую область 0x40 Б, порт упирается в гейт `size_x <= xi`.
- **Обход:** офлайн порт исполняется только при `bdd0_grid_level_modelled() != 0`, иначе реплеится
  записанный натив (сводка `grid_anchor_replayed`). Включение — захват с объектом сетки (v16) плюс
  одновременное снятие обоих nested-сайтов и запись `0x458050` в `b0_ported_leaf_va` с claim из тела.

## `45b150`: слоты FX/FY не инициализируются — мусор стека вызывающего (24.11.2026)

- **Симптом:** A/B порта против нативного кода расходится только там, где первая итерация не взяла
  ни одной ветви: результат зависит от стека, а не от ленты.
- **Причина:** `FX/FY` (`E+0x28/E+0x2c`) — локалы в окне `E+0xc..E+0x2f`, которые тело ни разу не
  пишет до первого чтения `0x45b391`; натив читает чужой мусор ниже ESP вызывающего.
- **Обход:** порт инициализирует их нулём (как зануление неинициализированной тройки в B34/B78):
  конфигурации, где ветвь взята в первой итерации, совпадают бит-в-бит; все sentinel-вызовы пяти
  захватов имеют `px²+py² > 100` — там тот же `100.0f`. Окно расхождения — до первой взятой ветви.

## RE-ревью `458050`: ложный REJECT из двух ловушек вывода (24.11.2026)

- **Симптом:** ревью объявляет `[esp+0x30]` у 0x4580e3/0x45812e = arg2 (float-биты как tree-контекст) и «`best`-апдейт мёртв» → REJECT верного порта.
- **Причина:** ESP посчитан без `ret N`: вложенный `call 0x457e20` — `ret 0x10`, ESP восстановлен; паритет `TEST AH,0x5` выведен из «C0 == C2», а не из таблицы probe8.
- **Обход:** перед слот/ABI- и mask-claim'ами считать ESP через каждый push/sub/call+ret; семантику масок брать из `re/battle_ai_x87.md §1` (таблица probe8).

## Лист `45e1d0`: `pf+0xNN` через `BattleAI*` масштабируется на `sizeof` (26.11.2026)

- **Симптом:** порт листа исполняется (`path_recompute_port=364`), но `path_post_match` видит
  `pf+0x28 port=0x00000000` при `post=0x1ef9…`, а часть тиков ловит trap.
- **Причина:** `BattleAI *pf`, `pf + 0x28` — это `+0x28*sizeof(BattleAI) = +0x1360`; записи полей
  уходили за область арены (страница `PAGE_NOACCESS`), pf оставался прежним.
- **Обход:** в `battle/recompute.cpp` блок pf адресуется как `unsigned char *` (`pf + 0x28` — байты).

## `arena_raw_of` и «синтетические» bind-и: обратный перевод shadow→raw врёт (26.11.2026)

- **Симптом:** `leaf_args` падает на `ecx port=0x00961fc0 native=0x00ec1fc0` (`458050`) после того,
  как тем же `arena_raw_of` начали сверять указатели листа `45e1d0`.
- **Причина:** уровни сетки биндятся по синтетическому адресу `rec->tree + i*0x30` (`materialize_models`),
  а не по адресу из захвата; обратный перевод такого bind-а даёт не адрес игры.
- **Обход:** `Bind.synth` (`bind_add_ex`), `arena_raw_of` их пропускает; `cmp_ptr` применяет identity по
  bind-карте только когда shadow-указатель порта вне именованных областей снимка (`pn == NULL`).

## Заявка листа, вызванного изнутри тела другого листа, ломает `leaf_seq` (26.11.2026)

- **Симптом:** `leaf_seq: leaf claim #1: requested va=0x458050, recorded va=0x45e1d0`.
- **Причина:** тело `0x458050` в конце заявляет своё значение (`grid.cpp` claim); при вызове из тела
  `0x45e1d0` его запись лежит в окне `bdd0_nested`, а не в потоке тика — заявка «съедает» чужую запись.
- **Обход:** `b0_leaf_claim_suspend(1)` на время вложенного исполнения (`recompute.cpp path_grid_anchor`),
  значение сверяется с записью границы через `b0_nested_expect_ptr` (символьно, shadow→raw).

## Порт `45e1d0`: кандидат скана с общим блоком арены теряет идентичность (26.11.2026)

- **Симптом:** новая проверка `path_boundary_args` валит 247 тиков: `site 0x45e46b va=0x45dd70 arg[0] port=0x01251fa8
  recorded=0x200c6f40` — один и тот же shadow-адрес на всех итерациях P9.
- **Причина:** блок под PathState-кандидата (`b0_cand_materialise`) переиспользовался на тик, а `arena_raw_of`
  возвращает первый bind, содержащий адрес, — обратный перевод указывал на первого кандидата.
- **Обход:** своя область арены на каждый записанный адрес кандидата (`path_cand_<raw>`), `ARENA_REGS_MAX` = 96
  (база + вход листа + блоки реплея + до 34 кандидатов); идентичность кандидата нужна картам и сверке аргументов.
