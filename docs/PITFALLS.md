### Мигание окна при смене фокуса и ловушка `WS_EX_COMPOSITED`

**Симптом:** экран мигает при alt-tab и при смене фокуса; попытка лечить через `WS_EX_COMPOSITED` ломает запуск игры.


- `[P]` Источник flashing при смене фокуса: видео wndproc `FUN_0049a4f0` на
  `WM_LBUTTONUP (0x202)`, `WM_RBUTTONUP (0x204)`, `WM_LBUTTONDBLCLK (0x205)`
  делает `ShowWindow(DAT_0051d5e8, 0)` = **SW_HIDE** (адрес rva 0x49a571,
  fileoff 632177, байты `6A 00 50 FF 15 1C`).
- `[P]` `WS_EX_COMPOSITED` для движковых окон **неприменим**: оба класса окон имеют
  `CS_OWNDC` (`style=0x28` main, `0x23` video; CS_OWNDC обязателен для wgl).
  По MSDN WS_EX_COMPOSITED не работает с CS_OWNDC/CS_CLASSDC; живой P/Invoke-тест:
  `CreateWindowExA(0x20040000,...)` → NULL, `GetLastError=87`
  (ERROR_INVALID_PARAMETER). Патч exstyle (`push 0x40000` → `push 0x20040000`) ломает
  запуск игры (EXE выходит сразу) — проверено живым прогоном.

**Обход:** однобайтовый патч SW_HIDE→SW_SHOWNORMAL на fileoff 632177 (в baseline `45e93d46…`,
`tools/exe/apply_baseline.py`) + borderless-патчи `tools/exe/exepatch3.py` (`CDS_FULLSCREEN→CDS_TEST`,
`NULL_BRUSH`, снятие рамок). `WS_EX_COMPOSITED` не применять (проверено живым прогоном: EXE выходит
сразу). Полный набор правок — `docs/PATCHES.md`, раздел Borderless.

**Симптом:** «положительные» эффекты масштаба на сайте draw, зарегистрированные в прошлой итерации, при точном
дизасембле оказались тождеством; все правки полей пула — ноль эффекта.


## Итерация 2026-11-15 (вечер): фильтр/гейт на сайте 0x470932 — отрицательные результаты и разгадка
- `[P]` **Полный «рабочий» статический cave (exepatch6, PARTS full) математически = тождество.**
  Точный дизасембл байтов (fileoff 0xebf12, 234 байта): loop1 суммирует поля `+12/+16`
  (`w=-1`, `color`) всех 4 записей; center = sum/4 = среднее тех же значений; loop2 пишет
  `x' = 0.75·x + 0.25·center = x`. Запись байтов обратно идентична исходным. Следовательно
  «сжатие 538→300», зарегистрированное в прошлой итерации, было **артефактом состояния меню**
  (hover/no-hover), а не эффектом патча. Все мои реплики честно воспроизводили тождество —
  этим объясняются нулевые результаты каждой проверки.
- `[P]` Точная раскладка записи: record base = `esi + idx*32` (stride 0x20); поля: `+0=0`,
  `+4 u`, `+8 v` (координаты сигнатур, значения 538/682/586…), `+12 w=-1`, `+16 x`, `+20 y`,
  `+24..` флаги corners (1,0)/(1,1)/(0,1)/(0,0) (`f5,f6`). Сигнатуры стрипов
  (min u, min v, w, h) в hooklog4 = поля +4/+8 (это `u,v`, НЕ экранные x,y).
- `[P]` **Запись в поля записей пула (`u,v`, `x,y`, `w`, `color`, флаги) не меняет рендер** —
  многократно проверено на живом сайте при нативно сработавшем фильтре (debug-счётчик в
  `.data 0x51d500` ≈200 инкrementов за 2 с при hover (2400,1750)): масштаб `u,v`, `x,y`, `w`,
  flags — визуально ноль. Пул не является живым источником вершин glyph-квадов (geometry
  загружается один раз).
- `[P]` Инструментальная lesson: `movl 16(%esi,%edx,1), %eax` затирать счётчик цикла (`test
  eax,eax`) → вылет за пределы индексов → краш (`wrec` ALIVE False). Поле читать в `%ecx`.
- `[P]` Debug-счётчик cave обязан лежать в writable `.data` (VA `0x51d500`); `incl` в RX
  `.text` (0x4f5310) — краш игры. Счётчик читается Frida `rpc.exports`, сброс через
  `Memory.patchCode(base+0x1d500)`.
- `[P]` Гейт по значению окна через user32 из cave (`call [GetForegroundWindow 0x4ec1c0]`,
  `GetClientRect 0x4ec1cc`, сравнение right==3840) — **убивает игру** даже без scale-блока
  (проверено и в нативном cave, и в Frida-эмуляции NativeFunction). Не использовать.
- `[P]` Глобальной переменной разрешения нет: скан процесса (модуль + все rw-регіоны) на
  int-пару (3840,2160)/(1024,768) и float-пару (3840.0,2160.0) — 0 совпадений. В куче есть
  float 3840.0 в адресе bddfba0 (+2161.0) — адрес плавает, для статического патча непригоден.
- `[P]` Уникальные для 4K сигнатуры записей: `minx=417` (282/phase при hover; в 4:3 есть
  только 414/423), max u=682/703 (4:3 max 547, но 600..1024 значения есть и в 4:3) —
  точный band-гейт `415<minx<419` работает (фильтр fires), эффект масштаба = ноль.
- `[P]` 20 «низкочастотных» сайтов (235-239/phase) = per-frame GL state-вызовы, НЕ glyph
  draws; draw-сайты в файле: только `0x4707b7` (в меню не стреляет) и `0x470932`.
- `[P]` Итого за итерацию: ни одна комбинация «поле + фильтр + scale» на сайте 0x470932
  не дала видимого сжатия текста; все прежние «положительные»测量 — артефакты hover-состояния.
  **Задача (уменьшить шрифт при 4K правкой сайта draw) на этом сайте закрыта как бесперспективная:**
  geometry glyph-квадов не читается из пула при draw.
- `[P]` Состояние: EXE = чистый baseline (md5 `45e93d46aad6ceb3dfc17e86d04e4f82`), игра
  остановлена. Рабочие скрипты итерации: `tools/archive/cave_gen/cavesrc.py` (range/eq-фильтры), `tools/archive/cave_gen/cavew.py`
  (record-band + w scale, исправлен), `tools/archive/cave_gen/caveext.py` (extent-фильтр), `tools/archive/cave_gen/cavegate.py` (u>600),
  `tools/archive/cave_gen/cavegate417.py` (minx-гейт 4K-only), `tools/archive/cave_gen/cavegatew.py` (оконный гейт — краш), `tools/archive/cave_gen/cavefilt.py`
  (corruption на text strip).
- Следующий шаг: точка **загрузки** геометрии: site `0x470909` (`push eax; push 0x20; push
  0x1401; push 4; call [0x51cd50]` — загрузка шрифт-атласа, GL_TEXTURE_2D) — хук/патч там;
  разрешение брать из `hd.cfg` (читается при старте), а не из рендера.


**Обход:** задача «уменьшить шрифт при 4K правкой сайта draw» закрыта как бесперспективная; рычаг — путь
текста `0x477220`/`FUN_0041d020` (расцепить UV и advance) — реализовано пещерой на назначении шрифта:
`docs/PATCHES.md` (exepatch8/9/10/12). Снимки делать только при активном окне (`shot_activate.ps1`).


### Ловушки съёмки и Frida (перепроверка 2026-11-15)

**Симптом:** снимки дают байт-в-байт одинаковые PNG / «нулевые эффекты»; скрипты молча падают на каждом вызове.


- `[P]` **Крайне важная инструментальная ловушка №1: окно не перерисовывается, пока
  не в foreground.** Снимки `tools/archive/probes/probe_shotwin.ps1`/`tools/archive/probes/probe_dlgshot.ps1` после ухода курсора
  за окно давали БАЙТ-В-БАЙТ одинаковые PNG (md5 совпадал у 4 «разных» прогонов) — все
  «нулевые эффекты» на таких снимках недостоверны. Рабочая схема: активировать окно
  (`ShowWindow(SW_RESTORE)+SetWindowPos(TOPMOST)+SetForegroundWindow`) и снимать экран
  0,0 при активном окне — `tools/archive/probes/shot_activate.ps1`, дальше `ld_*_test.py` (утрачен: покрытия нет ни в git, ни в приватных архивах сессий Project/1-3.7z, 5.7z, 6.7z, 7.7z, original.7z, hd_pack.7z, python_libs.7z).
- `[P]` **Ловушка №2: в Frida 17 нет `Memory.writeByteArray`/`readByteArray`** — только
  `ptr.writeByteArray()` / `ptr.readByteArray()`. Скрипты, использовавшие Memory.*,
  молча падали на каждом вызове (и «ничего не меняли»).
- `[P]` **Ловушка №3: откат вершин в `onLeave` бесполезен/вреден** — драйвер читает
  client-arrays ПОЗЖЕ возврата из submit-функции. Проверено: сдвиг x на +300 без отката
  двигает весь текст; тот же сдвиг с восстановлением в onLeave — визуально ноль. Для
  статического cave это плюс: восстанавливать не нужно, буфер пересобирается каждый кадр
  (повторного накопления нет: +300, а не +600/+1200).

**Обход:** снимать экран при активном окне (`tools/archive/probes/shot_activate.ps1`), Frida-17 — только
`ptr.writeByteArray()`/`ptr.readByteArray()`, откат вершин в `onLeave` не делать (буфер пересобирается
каждый кадр). Frida-сессию закрывать до снимка: после долгого attach рендер умирает.

## Черезстрочные PNG: квадратная dims-амбигуность (2026-11-15, вечер)
- `[U]` «часть текстур криво сконвертировалось в png: `mm_ng_tt_transmuter`, `mm_tt_save`,
  `msg_btm_alt` — в png черезстрочные паттерны». бекап оригиналов:
  `scratch_dir('textures_original_btf2x')` (1270 `.btf`, mtime 2002–2003).
- `[P]` **Канонические dims** = первые два u32 после поля имени (`w`, `h`),
  `bpp = blob_len/(w*h)`; `blob_len` — последний u32 `i` c `i+4 == plen - v`
  (`hdr_end = plen - blob_len`). Поле имени: `(len u32, ascii)` — длина не кратна 4,
  поэтому поля после имени идут **со сдвигом**, и `parse_btf`, который сканирует пары по
  всем 4-выравненным офсетам и **предпочитает квадратную пару**, для `w != h` берёт
  ложную квадрaту: blob 262144 подходит и как 512x128 (bpp4), и как 256x256 (bpp4).
- `[P]` Затронутые файлы (`.tmp/state_scan.py`, сравнение канонических dims с игрой):
  **5** — `fire01`, `mm_ng_tt_transmuter`, `mm_tt_save`, `msg_btm_alt` (512x128 bpp4) и
  `ship_deck01` (512x128 bpp3). Экспорт сделал PNG 256x256/256x256 (shear → черезстрочные
  линии), packer пропатчил **не** w,h (пара (256,256) в заголовке — ложная), а поле
  `w*h`/`blob_len`, так что в игре эти файлы = апскейл-blob при родных w,h: движок читает
  первые `w*h*bpp` байт = верхнюю полосу кривого апскейла. Остальные 1244 установленных

## Обязательные грабли проекта (симптом → причина → обход)

- **Интерактивный `7z` без `-y` при распаковке baseline** — стенд зависает на запросе перезаписи.
  Причина: архив содержит уже извлечённые файлы; `7z` ждёт ответа. Обход: флаги `-y` и
`stdin=devnull` в `tools/exe/apply_baseline.py` (исправлено коммитом `a06d5d5`).
- **`sys.path.insert(0,'C:/...')` в Cygwin Python 3.12** — модуль не находится
  (`ModuleNotFoundError`). Причина: cygwin-python не понимает windows-буквенные пути.
  Обход: `/cygdrive/c/...` (см. грабля выше).
- **PowerShell-скрипты не запускаются** — политика выполнения блокирует `.ps1`. Обход:
  `powershell -NoProfile -ExecutionPolicy Bypass -File <script>`.
- **Игровая установка read-only для инструментов**: любая запись в игру — только явным `--install`
  проверенных скриптов (`tools/pyc/install_patch.py`, `tools/exe/* --install`,

  base-печатью манифеста. Обход: base-печать собирается только с явным `pyc_source_mtime`

- **«`site.py` удалён» из документации сбивает с толку**: удалены только подложенные копии

  Обход: читать `Lib/`, а не искать `site.py` в корне; историческая пометка
  «файл удалён» относится к корневым копиям (`site.py`/`codecs.py` лежат в `Lib/`).

## Импорт 2.2.3 чувствителен к регистру имени модуля (плоский дамп установщика не импортируется)

**Симптом:** в дереве интерпретатора, собранном из плоского дампа `Python-2.2.3.exe`,
startup даёт `'import site' failed`, а `import site`/`os`/`string`/`UserDict` падает
`ImportError: No module named …`; worker'у не хватает stdlib, `check_state` на таком
`py223.dir` не проходит (`python3 tools/pyc/install_patch.py hd_scale` — compile-фейл).

Причина (измерено по источнику 2.2.3 и живыми замерами):
- `[P]` В `Python/import.c` (2.2.3) после удачного `fopen` кандидата вызывается
  `case_ok(buf, len, namelen, name)`; реализация MS_WIN32: `FindFirstFile(buf, &data)` и
  `strncmp(data.cFileName, name, namelen) == 0` — сравнение **точного имени файла** на диске
  с именем модуля. Файлы дампа (`STRING.PY`, `SITE.PY`, `USERDICT.PY`) не совпадают с
  `string`/`site`/`UserDict` → `case_ok` возвращает 0, модуль не находится.
- `[P]` FS-lookup регистронезависим: на том же файле `os.stat()` и `open()` успешны
  (`stat ok size 11943`, чтение полного файла), а `imp.find_module('string', [dir])`
  → `ImportError: No module named string`. read-путь работает, import-путь — нет.
- `[P]` `PYTHONCASEOK` — env var, при нём `case_ok` сразу возвращает 1: замер
  `PYTHONCASEOK=1 python.exe …` импортирует `STRING.PY` под именем `string`.
- `[P]` Плоский дамп установщика — это ровно содержимое `Lib/`+`DLLs/`+корня, имена в ВЕРХНЕМ
  регистре, каталоги `plat-win`/`lib-tk`/`idlelib` сплюнуты в один каталог (2145 файлов).
  Из него годятся бинары (`PYTHON.EXE` 20526 B, `PYTHON22.DLL` 847920 B) и DLLs; `Lib` — нет.

**Обход:** дерево интерпретатора собирается из `Python-2.2.3.tgz` (канонический `Lib/`
с регистром имён источника) + бинары/DLLs из дампа установщика; имена файлов — точный регистр
tgz. Замеренное дерево и его состав — `docs/TOOLS.md`, раздел «Тулчейн» (пункт «Дерево
интерпретатора»); проверка импортов и `imp.get_magic()` в нём — там же.

## Пересборка `.tex`-записи в `.map`: два грабля, дававшие краш (2026-11-17, вечер)

- `[P]` **Лишний `name_len` u32-префикс при пересборке записи.** `scan_tex.py` даёт
  `name_off` = строка имени; родной `name_len` u32 лежит в gap'е перед именем. Если
  `rec_bin` собирать как `pack('<I', name_len) + name + hdr + blob`, все поля записи
  сдвигаются на +4: 2-байтная short-проверка разбора (`FUN_00495300`, младший байт
  обязан быть 0) читает мусор, FACT (`FUN_00495720`) возвращает NULL, диспетчер
  снимает NULL на `0x467f54` → `0xC0000005` (ExitCode `0xC0000005`, WER fault
  offset `0x67f54`). Правильно: `rec_bin = name + hdr + blob`.
- `[P]` **TLV-размеры наружных заголовков обязаны расти вместе с blob'ом.** Payload
  ходит ADV (`FUN_0049bf70`) по цепочке заголовков `(type u32, size u32)`
  (содержимое `pos+8..pos+8+size`, следующий заголовок `pos+8+size`): размер внешнего
  заголовка записи (u32 по `name_off-28`) и размер каждой накрывающей секции
  (для `portal_domain.map` — заголовок @2986660 `type=130`) равняются длине содержимого.
  Если оставить старый размер, ADV сбивает координаты потока, FACT NULL, краш
  (`0x467566` — обход тайлов почвы `FUN_00467540`). Правка —
  `tools/tex/patch_map_pattern.py` (`chain_headers` + `fix_chain`, с пересчётом
  позиций после вставок). Дельта прибавляется (+ при апскейле, − при даунскейле).
- `[P]` Живой прогон игры переписывает базовые шрифты установки родным содержимым:
  `data/fonts/ld_{numbers15,tahoma11,uncial12,uncial20}.{fdf,btf}` при выходе движка
  получают native-размеры (fdf 216/3386/2730/2730, btf 1557/4152/40595/56322) вместо
  HD-набора `config[assets.hd_pack]` (240/3659/2879/2916, 51722/838201/971697/1461036).

## Боевая камера: `SetScale` ≠ зум, `RotateAroundY` в радианах (18.11.2026)

- `[P]` **«`SetScale` = зум» — неверно.** Единственный «масштабный» метод камеры
  (`0x4125c0`, формат `f`) умножает поля `camobj+0xf8/0x10c/0x13c`; A/B-снимки при
  `scale=1.0/2.0/0.795` различаются только анимацией (HUD-зоны `mean=0.0000`,
  центр мира `mean=0.18`). **Обход:** зум = высота камеры над землёй (как
  `olcamera.h_togglezoom_d`), fov (`camobj+0x144`) из Python недоступен.
- `[P]` **`SetOrtho(...)` сбрасывает камеру в (0,0,0)** — сразу после вызова
  `GetPos()` = `[-0.0, -0.0, -0.0]`. Не использовать как «переключатель проекции».
- `[P]` **`RotateAroundY` принимает радианы, а `Rotate` — градусы.** Симптом: камера
  вращается в ~20 раз быстрее ожидаемого («прокрутка» на 180° за снимок).
  Проверка: клавиша «turn_left» с `turn_speed=1.75` за 0.9 с даёт ровно 90°
  (1.75·0.9 рад) → единица = радиан. **Обход:** чувствительность задавать в
  радианах на единицу отклонения (`mmb_sens = 0.012`), наклон — в градусах.
- `[P]` **Уроки «Игровая камера и панели» не снимаются Enter'ом.** 15 и 30 Enter не
  помогают: урок ждёт действия игрока, «Далее» на нём заблокирована
  (`btutorial.EnableNext(0)`), на экране «Игра в паузе». **Обход для тестов камеры:**
  либо замерять прямо на уроке (камера обновляется — `hB_Update` идёт), либо входить
  в бой через загрузку сейва → оверленд → клик по планете → «Атака» (путь
  пользователя), либо через `mainmenu.DebugAttack(<id>)` (минуя `newgamemenu`,
  который и включает уроки).
- `[P]` **PowerShell: отрицательное числовое значение в позиционном аргументе**
  (`-40`, `-3`) разбирается как имя параметра, и в функцию уезжает строка
  (`"-25-25-25…"` → `InvalidCastFromStringToInteger`). **Обход:** `([int]-40)`.
- `[P]` **`hd.cfg` в установке содержит лишнюю строку-комментарий**
  (`3840 2160 32 1\r\n#1280 960 32 0`), из-за чего `--quick` печатает
  `DRIFT cfg hd.cfg` (mtime 08:10 18.11, до сессии камеры). Это не следствие
  патчей камеры; при желании лечится копией `hd.cfg` из корня репозитория
  (`fix_command` чекера — `pycbuild.py install-min`).
