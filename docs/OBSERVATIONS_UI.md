## Контрольный замер 16:9 в окне 1920x1080 (hd16/hd17, 2026-11-14)
- `[P]` Конфиг `hd.cfg = 1920 1080 32 0`; окно физически 1920x1080 (DPI-виртуализации
  в этом прогоне нет). `k = 1080*1024/(1920*768) = 0.75`, `dx = 128`.
  UI-бокс: движковые границы x∈128..896 → физический бокс x∈240..1680 (ширина 1440,
  по центру), y = весь кадр (высота 1080) — геометрия 16:9 корректна.
- `[P]` **X-формулы подтверждены**: все 6 OS-точек прогона легли на `m = P/sx`
  (sx = w/1024 = 1.875) и `MC = (m-dx)/k`; экранная позиция билборда = P identity
  (курсор по X точно под указателем).
- `[P]` **Y-семантика в окне**: живой центр-тест подтвердил **`MY(m) = m`** при F=0
  (белая точка под указателем, пользователь подтвердил). `hd_scale` без константы
  `HD_BORDERLESS`; `MY = m` при F=0, `m/k` при F=1; при k=1 identity.
- `[P]` Аномалия логов: при одном конфиге `MY=m/k` дал y(0.1,0.1)=−48, `MY=m` дал −92,
  отношение смещений = 1/k² — движок возвращает позицию с обратной связью
  (Python шлёт ему `EC/EY` через `SendMessage(WT_MOUSE)`), поэтому логи по Y
  не самосогласованы, решение — только живой тест.
- `[U]` Окно 1920x1080 (сборка `MY=m`): «всё ок» (центрирование, UI, клики).

Реализация (правка `patches/ui/battlemenu.py`) — `docs/PATCHES.md`, раздел «Боевой HUD поверх recovered-базы».
