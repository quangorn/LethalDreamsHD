# Перепроверка HANDOFF: что оказалось неверно (2026-11-15)

## 1. Раскладка вершины в HANDOFF неверна

Реальная запись GL-вершины (stride 0x20), доказана дизасемблом `FUN_004708d0` и живым дампом:

| offset | поле |
|---|---|
| +0x00 | float x |
| +0x04 | float y |
| +0x08 | float z (= -1) |
| +0x0c | цвет RGBA, 4 байта |
| +0x10 | float u (0..1, texcoord) |
| +0x14 | float v |
| +0x18 | padding |

В логгере `ld_phases2.py` база бралась как `esi + 0xc + idx*32`, а на сайте `esi = V + 0x10`
(после `add esi,0x10`). Итого сдвиг +0x1c: логгер печатал padding + СЛЕДУЮЩУЮ запись
(x, y, z, color, u, v). Отсюда весь «layout u,v,w,x,y» HANDOFF и «сигнатуры 538/417»:
это экранные координаты соседней вершины, не UV.

Cave `exepatch6` масштабировал `[esi+ebx+0xc]` и `[esi+ebx+0x10]` = padding и x следующей
записи. «Тождество» и «нулевой эффект» объясняются ошибкой адресации, а не отсутствием рычага.

## 2. UI рисуют два живых пути

- `0x470932` — glDrawElements: вся растровая графика (рамка диалога, иконки, кнопки).
  Сдвиг x на -100: рамка и иконки исчезают, текст остаётся.
- `0x477220` — glDrawArrays: ВЕСЬ ТЕКСТ. count=0 → текст исчезает, графика остаётся.
  count=0 на обоих → пустой экран.
- Класс B (`0x4706e8` / `0x4707b7`) вообще не вызывается.

Текст строит `FUN_0041d020` (вопреки старой записи «не срабатывает»): ~18.6k вызовов
за 2.5 с при открытом диалоге. Аргументы: `(float x, float y, char* text, ...)`, `ret 0x14`.
Текст рисуется в абсолютных канвас-координатах (modelview = identity).

## 3. Три ловушки, которые объясняют все прошлые «нули»

1. **Окно не перерисовывается, пока не в foreground.** Четыре «разных» прогона дали
   байт-в-байт одинаковые PNG (совпадал md5). Снимать только после активации окна
   (`shot_activate.ps1`).
2. **В Frida 17 нет `Memory.writeByteArray`** — только `ptr.writeByteArray()`. Скрипты
   падали на каждом вызове и «ничего не меняли».
3. **Откат вершин в `onLeave` бесполезен** — драйвер читает client-arrays позже возврата.
   Сдвиг x на +300 БЕЗ отката двигает текст, тот же сдвиг С откатом — визуально ноль.
   Для статического cave это плюс: откат не нужен, буфер пересобирается каждый кадр.

## 4. Что это значит для «апскейл текстуры + уменьшение при отрисовке»

Ограничение движка: ширина UV-ректа = advance из `.fdf` (`u2-u1 = adv/texW`), геометрия
квада тоже = advance x pitch. Поэтому «увеличить лист и рисовать мельче» требует расцепить
UV и геометрию в эмиттере (`FUN_0041d020` / `FUN_0041cc90`), иначе уменьшение advance
кадрирует глиф. Именно эту связку обходил `rescale_font4.py` — сжатием ink в ячейке,
отсюда и потеря качества на 4K.

Рычаг рабочий: `scale_arr.js` (мутация на `0x477220` без отката) реально двигает текст.
