# Задание-план: распаковщик `.tex` (почвенных текстур карты) → `.png`

## Цель

Получить офлайн-инструмент, который вытаскивает **почвенные текстуры карт** из
`config[game.root]/data/maps/<map>.map` и сохраняет их как PNG, чтобы:
1. видеть глазами, чем игра рисует землю (сейчас это недоступно ни в каком виде);
2. иметь эталон для будущего апскейла земли и, позже, для обратной упаковки;
3. снять вопрос «откуда берутся текстуры земли» полностью (сейчас закрыт только
   путь «источник → запечённый ресурс → материал», формат пиксельного blob'а — открыт).

Выход: `tools/tex/unpack_tex.py` (CLI, пакетный режим), эталонный дамп
`scratch_dir('ld')/tex_src/` (44 PNG + `MANIFEST.txt`), запись наблюдений в
`docs/OBSERVATIONS_TEXTURE.md`.

## Что известно (факты, проверённые в этой сессии)

- Каждая карта = 5 файлов в `config[game.root]/data/maps/`: `.map`, `.lt`, `.ndm`,
  `.py`, `.pyc`. Пути собираются в EXE, `FUN_004230c0` (строки `data/maps/%s.map`,
  `.lt`, `.ndm`, `.py`, `.pyc`).
- `data/maps/<map>.map` = тот же контейнер, что `.btf`: `LDPACKER` + zlib (`78 DA`)
  → payload. В payload'е — сетка геометрии **и почвенные текстуры с именами
  `<map>_<N>.tex`**. Прогон по всем 30 `.map`: суммарно **44 текстуры**
  (1..3 на карту): `bald_hill_0.tex`, `crossroads_0/1.tex`,
  `incarn_domain_0/1/2.tex`, `world_heart_0.tex` и т.д.
- На каждую `.tex` — пара сгенерированных материалов
  `config[game.root]/data/materials/<map>_opaque_<N>.pyc` и `<map>_alpha_<N>.pyc`
  (1:1, проверено на bald_hill/crossroads/incarn_domain/world_heart). Их текст
  печатает генератор карты (`FUN_004a5610`, строка
  `## this script was automatically generated by proclandlib`):
  `Passability = globalscript.GROUND` (или `WATER`), `AcceptCamera = 1`,
  `def InitMaterial( Mtl ): p = Mtl.GetPass( 0 ); p.AddTexture( "<map>_<N>.tex" )`;
  alpha добавляет `p.SetBlendFunc( globalscript.BBlend_Blend )`; вода — pass 1 с
  `envmap02.bmp`, `SetTCGenEnvironment`, `AddTCModScroll/Rotate`,
  `AddVertexDeformerWave_Sin`.
- Источник почвы для генератора: `config[game.root]/data/wrender/`
  (`GROUPS` — таблица `id|group|class|имя|путь|цвет`, 87 записей;
  `figures/textures/` — 120 BMP 32×32 24-бит RGB + 9 TGA;
  `figures/borders/` — 24 BMP 128×128; `figures/*.fgr` — 129 дескрипторов тайла,
  поле №5 = id текстуры из `GROUPS`) и схемы `config[game.root]/data/plscripts/**`
  (`domain.h`: `textures{ set alias "<имя GROUPS>" }`,
  `terrainmapping{ tex alias r g b a elev_start elev_end slope_start slope_end }`,
  `waterparms`, `roadparms`; `mapparms.h`: `size 100`, `texturesize 128` /
  `512` в доменах). Ключевые слова парсера есть в EXE (VA `0x4f46c0..0x4f4738`:
  `tex`, `terrainmapping`, `setgs`, `set`, `textures`, `light`, `nametbl`,
  `datapath`, `layer`, `slope`, `elevation`, `distmax`, `distmin`, `group`).
- **В runtime EXE строк `wrender`, `figures`, `.fgr`, `GROUPS` нет** — библиотека
  читается генератором, игра рисует только запечённую `.tex`. Значит конвертация
  `.tex` → PNG = единственный способ увидеть реальную почву игры.
- Структура записи `.tex` (срезы по 6 картам): после имени id-поля `2,2,0` / `4,4,0`
  (`alpha/opaque`?), затем `2,2,0`, `1,1,1`, поле type=`117`(0x77), поле count
  (`0x0c` у `bald_hill_0.tex`, `0x30` у `incarn_domain_0.tex`), и дальше пиксельный
  blob до конца payload'а.
  - `crossroads_0.tex`: поля `1024, 1024` (размер), blob = 5 587 947 байт,
    `len % 3 == 0`, первые пиксели — RGB-триплеты `(13,34,09) (1b,3a,0e) (1b,33,0c)…`
    (цветная почва).
  - `bald_hill_0.tex`: blob = 2 735 798 байт, `len % 3 == 2`; первые пиксели почти
    все серые триплеты (`636363 707070 6c6c6c …`); всего 911 932 триплетов,
    из них 30.5 %.gray, 140 515 уникальных цветов.
  - Поле `33554432` (32 MiB) в заголовке — движковый лимит blob'а (`[P]` из
    `docs/OBSERVATIONS_TEXTURE.md`), он же лимит будущего апскейла.
- Движковый API пиксели не отдаёт (`GetFromScreenRect` без аргументов = 0,
  pickle Texture = segfault) — раскод обязателен офлайн (`docs/KNOWLEDGE.md`).

## Фаза A — экстрактор без декода (`tools/tex/scan_tex.py`)

1. Для каждого `data/maps/<map>.map`: decompress payload (zlib, magic `78 DA`),
   найти все вхождения regex `[A-Za-z0-9_\-]+\.tex\x00`.
2. Для каждого вхождения зафиксировать: offset имени, байты «шапки» до начала
   пиксельного blob'а (u32-поля), offset blob'а, длину blob'а (= до конца payload'а
   для одиночной записи; для карт с 2..3 текстурами — до начала следующей записи).
3. Сохранить сырые blob'ы в `scratch_dir('ld')/tex_raw/<map>_<N>.bin` и
   `MANIFEST.txt` (`имя offset_blob len поля...`).
4. Гейт фазы: все 44 записи извлечены, длины суммируются в payload корректно
   (Σ blob + Σ шапок + преамбула карты == len(payload)), дубликатов имён нет.

Только чтение игры; запись — исключительно в `scratch_dir`.

## Фаза B — определение формата пиксельного blob'а

Кандидаты, каждый с тестом предсказательной силы. Порядок: H1 → H3 → H2 → H4.

- **H1: raw 24-bit RGB, row-major** (канон `.btf` — `docs/OBSERVATIONS_TEXTURE.md`:
  top-down, порядок каналов RGB). Тест: `len == w*h*3` при w,h из полей шапки
  (у `crossroads_0.tex` поля `1024,1024` → 3 145 728;blob 5 587 947 — не совпадает,
  значит есть additional-слой: mip-цепочка, alpha-плоскость или RLE).
  Кандидальный тест для mip: Σ(w²)·3 по геометрической прогрессии.
- **H2: raw RGB + отдельная alpha-плоскость** (`w*h*3 + w*h`, как у `ol_r_bkg`
  в `.btf`). Тест: остатки длины (blob − w*h*3) кратны w*h.
- **H3: RLE (count + color-triplet)** — правдоподобно по структуре: длина `bald_hill`
  не кратна 3, поле count (`0x0c`/`0x30`) стоит перед потоком. Тест: полный проход
  по blob'у должен съедать ровно все байты (0 остатка) и давать ровно w*h пикселей.
  Разновидности: count u8 / u16, color 3 байта / 1 байт (gray), «count=0» = literal-run.
- **H4: indexed + внешняя палитра** (как 7 мелких UI-глифов, поле `'x'`,
  blob < w*h). Тест: `len < w*h` — для `.tex` не выполняется, маловероятно.
- Метод разрешения: **known-answer**. Почва генерируется из тайлов
  `figures/textures/<stem>.bmp` (32×32, RGB) с множителем цвета из
  `terrainmapping{ tex alias r g b a }` (`[P]` выше). Значит:
  1. посчитать цветовые статистиками каждого blob'а (уникальные цвета, доля gray,
     гистограмма) и сверить с ожидаемой палитрой тайлов карты + её schema;
  2. проверить seam-структуру: `figures/borders/*` — маски переходов; на декоде
     должны быть видны границы тайлов 32×32 (или 128×128 по `texturesize`);
  3. глазами сравнить декод с реальным экраном оверленда той же карты
     (`probe_loadshot.ps1` грузит сейв и снимает окно) — совпадение цветов/паттерна
     = подтверждение раскода; порядок каналов и ориентация (top-down/bottom-up)
     определяются этим сравнением, как в `.btf` (`mm_bkg01`, `treant01`).
- Гейт фазы: для всех 44 blob'ов один и тот же раскод даёт корректные размеры
  и полное покрытие байтов; три карты (bald_hill, crossroads, incarn_domain)
  сверены глазами с снимками оверленда.

## Фаза C — декодер и PNG (`tools/tex/unpack_tex.py`)

- Только Python 3, stdlib (`zlib`, `struct`, `re`), без PIL — как `tools/btf/unpack_btf.py`.
- Переиспользовать `png_write`/`decode24` из `tools/btf/unpack_btf.py`
  (канон: top-down, RGB) либо вынести общий модуль.
- CLI по образцу существующего: `unpack_tex.py <map>.map -o <out.png> --index N`,
  `--batch data/maps scratch_dir('ld')/tex_src`, `--probe` (писать все варианты
  раскода для визуального отбора), `--flip/--vflip` (ориентация как в `.btf`).
- Выход: `scratch_dir('ld')/tex_src/<map>_<N>.png` (RGBA) + `MANIFEST.txt`
  (`имя w h bpp blob_len offset`), `README.md`. Пропусков быть не должно: 44.

## Фаза D — QC и фиксация

1. Побитовая сверка: пересобранный из PNG blob == исходный blob (round-trip
   lossless, как делалось для `.btf` round-trip).
2. Статистика по всем 44: размеры, bpp, уникальные цвета, доля gray, доля
   пикселей, совпадающих с тайлами `figures/textures/` карты (по schema `domain.h`).
3. Пользовательская проверка в игре: снимок оверленда ↔ декод той же карты.
4. Наблюдения — в `docs/OBSERVATIONS_TEXTURE.md` (новый раздел «Почвенные текстуры
   карт (`.tex` в `.map`)»: формат, раскод, охват, ограничения); путь «источник →
   запечённый ресурс → материал» — туда же; указатель — `docs/INDEX.md`;
   факты о картах (5 файлов, проclandlib, парсер keywords) — `docs/KNOWLEDGE.md`.
5. После всех записей: `python3 tools/check_state.py --quick` rc 0; снапшот md5+mtime
   установки до/после — diff обязан быть нулевым (запись в игру не делается).

## Фаза E — обратный путь (отдельная задача, не в этом плане)

`pack_tex.py` (PNG → blob + шапка + контейнер `LDPACKER`+zlib level 9, по образцу
`tools/btf/pack_btf.py`), ограничения: лимит blob'а 32 MiB (`33554432`), размер
берётся из PNG; проверка — round-trip lossless на всех 44. Установка в игру —
только явным `--install` с md5-сверкой, бэкап оригиналов в
`paths.btf_backup_dir()`. Отдельный вопрос: меняет ли генератор `.tex` при
загрузке карты (тогда правка `.map` бессмысленна) — проверяется снимком до/после
правки на scratch-дереве (`LD_CONFIG` с другим `game.root`).

## Правила и запреты

- Игра — **только чтение**. Никаких записей в `config[game.root]`, EXE/DLL не патчить.
  Эксперименты — на scratch-дереве / копиях.
- `PYTHONDONTWRITEBYTECODE=1` при всех запусках; личные пути только в `config.toml`.
- Скрипты в `tools/tex/` (новые) — канонические команды `python3 tools/tex/<file>.py`
  из корня репозитория; добавить их в `docs/TOOLS.md` и `docs/PIPELINE.md`.
- Производные дамп-файлы (`scratch_dir`, `cache`) в git не входят.
- Один за раз: CLI, затем пакетный режим; кандидатный раскод писать в scratch,
  печатать параметры (w, h, layout, каналы, остаток байтов).

## Критерии готовности

1. 44/44 `.tex` извлечены, манифест полон.
2. Единый раскод даёт полное покрытие байтов всех blob'ов и согласованные размеры.
3. Три карты сверены глазами с снимками оверленда; каналы/ориентация подтверждены.
4. Round-trip lossless (blob → PNG → blob) побитово для всех 44.
5. Наблюдения зафиксированы в `docs/OBSERVATIONS_TEXTURE.md`,
   `docs/KNOWLEDGE.md`, `docs/INDEX.md`; `check_state.py --quick` rc 0; снапшот
   установки diff = 0.

## Открытые вопросы (зафиксировать, не «угадывать»)

- Точный формат blob'а (см. H1–H4) — сейчас не распакрашен; длина `bald_hill`
  blob'а не кратна 3, у `crossroads` кратна — единый raw-раскод не подтверждён.
- Что кодируют поля шапки (`2,2,0`/`4,4,0`, `1,1,1`, count `0x0c`/`0x30`,
  `65536`, `33554432`).
- `.ndm`: строк `.ndm` в EXE нет, назначение неизвестно.
- Генерация `.tex` при загрузке карты (возможна: schema+GROUPS есть в EXE) —
  если да, то правка `.map` не работает, путь апскейла земли — правка
  `figures/textures/` + schema.
