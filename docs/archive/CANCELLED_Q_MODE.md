## R/E/F1: формула «квадратный диалог по центру» (Q-режим) — план патча — ОТМЕНЁН
[!] План реализован как Q-режим и 16.11.2026 отменён (экраны меньше 4:3, клики мимо).
Оставлен только как история; рабочее решение — «R/E/F1: финальное решение».

- `[P]` Правильная геометрия (проверено расчётом): движковый квант fullscreen `s=w/1024`
  (4K `s=3.75`), цель = канвасный квадрат 1024x1024 -> square screen `h x h` по центру.
  Единный множитель `q = h/w` (16:9: `q=0.5625`):
      x_engine = q*cx + 512*(1-q) (= 512 + q*(cx-512))
      y_engine = q*cy
      w_engine = q*cw, h_engine = q*ch
  -> screen X = s*x_engine = (h/1024)*cx + (w-h)/2, screen Y = (h/1024)*cy.
  При 4K: квадрат screen x=840..3000 (шир 2160), y=0..2160, центр x=1920=w/2;
  screen-масштаб канваса = h/1024 = **2.109** px/канвас (против 4:3 1.875 -> x1.124;
  против текущих контролов 16:9 2.8125 -> x0.75).
  При 2K-F1 (2560x1440): квадрат x=560..2000, y=0..1440, масштаб 1.406.
  При 4:3 (`k=1`) = identity (патч не применяется).
- `[P]` Это даёт ровно то, что просит пользователь: окно **по центру экрана** и
  **вписано по высоте** (высота квадрата = высота экрана), без растяжения aspect.
- `[P]` Схема патча (Q-режим в `hd_scale`):
  - `HD_Q = h/w` при `k<1`, иначе identity;
  - движковые трансформы Q-режима: `ECQ(x)=q*x+512*(1-q)`, `EYQ(y)=q*y`,
    `SCQ(w)=q*w`, `SYQ(h)=q*h`, мышиный обратный `MCQ(mx)=(mx-512*(1-q))/q`, `MYQ(my)=my/q`;
  - метрики: движковый `GetTextWidth/GetFontSize` -> канвас = движок / q;
    `SetFont(size*q)`, RowS/Leading/TextOffset * q;
  - включение Q-режима ТОЛЬКО для квадратных полноэкранных диалогов: корень
    `research_dlg` (`re_bkg.tga` (утрачен: покрытия нет ни в git, ни в приватных архивах сессий Project/1-3.7z, 5.7z, 6.7z, 7.7z, original.7z, hd_pack.7z, python_libs.7z)), энциклопедия (`encyclopedy_scr.tga` (утрачен: покрытия нет ни в git, ни в приватных архивах сессий Project/1-3.7z, 5.7z, 6.7z, 7.7z, original.7z, hd_pack.7z, python_libs.7z), `enmenu`),
    help-оверлеи `help_dlg_ex` (`qrs_*.tga`). Фон этих rect'ов НЕ должен идти через
    `_is_bg` pass-through (иначе frame растягивается на весь экран).
  - дети идут тем же transform (линейный) — колонки/иконки сохраняют пропорции;
    hit-test и скроллбары через MCQ/MYQ.


**Обход:** план отменён; рабочее решение — обычная k-схема (`docs/PATCHES.md`, «R/E/F1: финальное решение»).



## ~~Q-режим (квадратные диалоги)~~ — ОТМЕНЁН 16.11.2026, код удалён

Ниже — история неудачной попытки (оставлена для контекста). Итоговая рабочая схема —
следующий раздел «R/E/F1: финальное решение». Причина отмены: модель «1024x1024 →
экранный квадрат со стороной h» неверна для этих экранов (их видимая композиция —
обычный канвас 1024x768), из-за чего окна выходили меньше 4:3-эталона, а хит-тест
считался k-схемой при q-прямоугольниках → клики мимо. Q-листы шрифтов и правки
bspellbook/enmenu/help не нужны и удалены.
- `[P]` Q-ядро `hd_scale`: при k<1 q=h/w, `ECQ(x)=q*x+512*(1-q)`, `EYQ(y)=HD_SYQ*y`,
  `SCQ/SYQ = q*размер`; `HD_SYQ = h/(1024*квант_y)` (= q в fullscreen, 0.75 в окне).
  Гейт: при k>=1 `q=1, QX=0, SYQ=1` -> все Q-функции identity (4:3 побитово без изменений).
  Q-область opt-in: `QOn()/QOff()` в диалогах; элемент помечается `self.HDQ=1` при
  InitBillboard, его `_push`/`InitBillboard` идут Q-rect'ом (`qmk`).
- `[P]` Масштаб глифов per-context решён БЕЗ EXE: движковая нормировка шрифта задаётся
  пещерой exepatch12 множителем `k*0.25` от листа (`FUN_0041cc90`, cave1 scale = pitch*k*0.25;
  GetFontSize = pitch_листа * k*0.25, live-подтверждено probe: tahoma1q pitch 57 -> fs=11,
  uncial2q pitch 114 -> fs=21, uncial1q 75 -> fs=14, base uncial20_169 152 -> fs=29).
  Для Q-контекста сделаны ОТДЕЛЬНЫЕ Q-листы = активные 16:9 листы, сжатые в q/k = 3/4
  (генератор `gen_fontq.py` (утрачен: покрытия нет ни в git, ни в приватных архивах сессий Project/1-3.7z, 5.7z, 6.7z, 7.7z, original.7z, hd_pack.7z, python_libs.7z)), и Python подменяет словари на время открытого Q-диалога.
- `[P]` Механика подключения шрифтов (из EXE): `LoadFont(name)` -> путь `Data\Fonts\<name>.fdf`
  (FUN_0041d460), fdf header `name pitch sheet.tga` (утрачен: покрытия нет ни в git, ни в приватных архивах сессий Project/1-3.7z, 5.7z, 6.7z, 7.7z, original.7z, hd_pack.7z, python_libs.7z); лист ищется material-реестром
