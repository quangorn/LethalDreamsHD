  Центрирующий Y-сдвиг **тождественно равен 0**: движковый центр окна = 384 =
  `384*1`; fullscreen = `h/(2s) = 512h/w = 384k` = `384*HD_SY` — канвасный центр
  попадает в центр экрана сам, `DY_E=0` всегда.
  Замеры (чёрный фон, `measure_ring4` tight-маска тора, кроп по центру экрана):

## exepatch4 — тестовое уменьшение advance шрифта в EXE (kx при parse)
- Скрипт `приватный архив сессий Project/1.7z, entry LethalDreams/exepatch4.py` (исторический скрипт сессии; в git не входит); бэкап `backup/LETHALDREAMS.EXE.pre4` (exepatch3 build, md5 45e93d46...).
  Патченный md5: `f6b4bd5f149a111118418cb5932f1409`.
- Смысл: при парсинге `.fdf` slot4 (advance, [+0x6c]) умножается на kx = h*1024/(w*768)*0.25.
  Для 4K 16:9 kx=0.1875 (текст ~4x уже), для 4:3 kx=0.25. Ширина глифов растёт вместе с advance
  (FUN_0041cc90 u=(x+adv)/texW), высота = pitch без изменений. Текстуры листов пока родные.
- Sites (VA, exepatch3 build):
  - site2 0x41cf52: 'mov [eax+0x6c],edx' -> jmp Cave_P@0x51c000; resume 0x41cf59;
    Cave_P: fild DWORD [esp+0xc]; fmul kx; fistp DWORD [esp+0xc] (DB/3); replay mov ecx/mov [eax+6c]/mov edx; jmp back.
  - site3 0x477df5: 'sub esp,0xd0' -> jmp Cave_K@0x51c036; resume 0x477dfb;
    Cave_K (SetDisplayMode(w,h,...), после 3 SEH push w=[esp+0xe0], h=[esp+0xe4]):
    fild h; fmul 1024.0; fild w; fmul 768.0; fdivp st(1),st(0) (de f9); fmul 0.25; fstp kx; add esp,0xd0; jmp back.
  - Константы (double): K_1024@0x51c088, K_768@0x51c090, K_T(0.25)@0x51c098, K_KX@0x51c0a0 (init 1.0), K_ONE@0x51c0a8.
- Зона пещер: .data VA 0x51c000..0x51c0ff (fileoff 0x11c000), RWE — правки заголовка не нужны.
- Verified: все 4 jmp lands совпадают; x87-энкодировки сверены с Intel/XED (FILD=DB/0, FISTP m32=DB/3,
  FMUL m64=D8/0, FSTP m64=DD/2, FDIVP ST(1),ST(0)=DE F9 — objdump читает DE C1 как faddp, не использовать);
  jmp rel32 land = patch_addr + r; патч-site resume = addr+5.
- Порядок при старте: gamescript Initialize -> SetDisplayMode (kx считается) -> парсинг .fdf (slot4*scale).
  Смена разрешения в игре не пересчитывает slot4 — нужен рестарт.

## Краевой скролл оверленда вниз: причина, A/B-замер, патч `ui/olcamera` (17.11.2026)

- `[U]` Симптом: «не работает скролл экрана мышью вниз; вверх, влево и вправо —
  работает»; проверка — загрузить сейв и двигать мышь к краям экрана. Подозрение
  пользователя: «связано с borderless-фиксом `+1 px` высоты окна».
- `[P]` Причина: `ui/olcamera.py` регистрирует обработчик мыши на сырое движковое
  событие `WMO_MOUSEMOVE`, поэтому пороги краёв (`>1021`, `==0`, `>765`) сравниваются
  с **движковыми** координатами мыши, а они канвасные. Движковый Y-диапазон = `768*k`
  = 576 при `3840x2161 F=1` → нижний порог 765 недостижим. `h+1` не причастен: при
  `h=2160` (`k=0.75`) тот же результат.
- `[P]` A/B-замер в scratch-дереве (полная копия установки 5097 файлов, `LD_CONFIG`
  на scratch-конфиг, зонд `y/x/thrY/pos` в `h_Update`, загрузка сейва «Вспомнить»
  → оверленд, курсор ОС по краям, прогон съёмки `probe_loadshot` + mover):
  патч `sf4`: порог `SY(765)=574`, мышь у нижней строки (`y=575`) → камера
  `(55.00,31.73)→(55.00,60.00)` = скролл вниз работает; база `sf6`: тот же `y=575`
  при пороге 765 → камера стоит. Верх/лево/право работают в обеих сборках.
- `[P]` Грабля scratch-прогонов: AppCompat-флаг `HIGHDPIAWARE` привязан к **пути** EXE,
  поэтому копия игры в scratch-дереве запускается DPI-unaware (окно виртуализуется до
  `6720x3780` при системных 175 % и выходит за экран, курсорные точки не соответствуют
  физическим краям). Обход: `set_layer.ps1 -GameRoot <scratch>` для пути копии; после
  него точка мыши и снимок совпадают с физическими. Точки mover в виртуализованных
  координатах = физические × 1.75.
- `[P]` Патч: `release/patches/ui_olcamera.patch` (2 ханка, +16 строк), метод
  `HDEdgeY()` = `hd_scale.SY(screen_size[1]-1)`; при `k=1` identity (регрессия 4:3
  побитово). Паритет базы 0.9974 (sig=0). Пайплайн `apply_patch.py ui/olcamera` +
  `install_patch.py ui/olcamera`; манифест — entry `ui/olcamera` (base-печать
  `f67ae9904032…` 11910 B, `.py` `4bf8df324ee6…` 8671 B, mtime 1794778203), кодовый
  ярус 11 .pyc, CODE-класс `--untouched` 15 → 16.
