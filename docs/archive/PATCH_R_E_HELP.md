# R / E / F1-помощь в 16:9: по центру и по высоте

Цель (запрос пользователя): экраны **R (Исследование)**, **E (Энциклопедия)** и все
экраны помощи (`qrs_*.tga`) при 16:9 рисуются по центру и вписываются в экран по высоте;
4:3 остаётся побитово оригинальным.

## Что установлено

Единственная правка — **`patches/hd_scale.py`** (модуль `hd_scale.pyc` в — компилят `.pyc` в установке, в git не входит
`data/scripts`). `bspellbook.py`, `enmenu.py`, `help.py` в игре остаются
**оригинальными** — их трогать не нужно.

### Как это работает

Шаблоны объявляют фон этих экранов как `billboardmain = [0, 0, 1024, 1024, ...]`
(`re_bkg.tga` (утрачен: покрытия нет ни в git, ни в приватных архивах сессий Project/1-3.7z, 5.7z, 6.7z, 7.7z, original.7z, hd_pack.7z, python_libs.7z), `encyclopedy_scr.tga` (утрачен: покрытия нет ни в git, ни в приватных архивах сессий Project/1-3.7z, 5.7z, 6.7z, 7.7z, original.7z, hd_pack.7z, python_libs.7z), `qrs_*.tga`). Но видимая композиция у них —
обычный канвас игры 1024x768: в 4:3 они заполняют экран целиком.

В 16:9 (`HD_K < 1`) такие фоны раньше попадали в `_is_bg` pass-through: движковый
rect оставался 0..1024 и растягивался на всю ширину (`s = w/1024`), поэтому картинка
была «зумленной» и обрезанной, а дочерние контролы (они уже в k-схеме) не совпадали
с фоном.

Теперь:

```python
DIALOG_TEX = ['re_bkg.tga (утрачен: покрытия нет ни в git, ни в приватных архивах сессий Project/1-3.7z, 5.7z, 6.7z, 7.7z, original.7z, hd_pack.7z, python_libs.7z)', 'encyclopedy_scr.tga (утрачен: покрытия нет ни в git, ни в приватных архивах сессий Project/1-3.7z, 5.7z, 6.7z, 7.7z, original.7z, hd_pack.7z, python_libs.7z)', 'player_dialog.tga (утрачен: покрытия нет ни в git, ни в приватных архивах сессий Project/1-3.7z, 5.7z, 6.7z, 7.7z, original.7z, hd_pack.7z, python_libs.7z)']
# + любой 'qrs_*' (все help-экраны)
```

`player_dialog.tga` (утрачен: покрытия нет ни в git, ни в приватных архивах сессий Project/1-3.7z, 5.7z, 6.7z, 7.7z, original.7z, hd_pack.7z, python_libs.7z) — фон `talk_dlg` (диалог с NPC, `ui/btalk.py`); добавлен позже
(16.11.2026) по тому же признаку: rect `[0,0,1024,1024]`, арт (альфа-bbox) занимает
канвас `x134..890 y6..643`, т.е. композиция — обычный канвас 1024x768.

* `InitBillboard` для такого фона не делает pass-through, а применяет обычные
  `EC/EY/SC/SY` и ставит на элемент метку `self.HDDBG = 1`;
* `_push` (SetPos/AutoPosition/SetPrior) для элементов с `HDDBG` тоже идёт k-схемой.

k-схема — это та же геометрия, что 4:3: канвас 1024x768 → 2880x2160 (при 4K) по центру
экрана. Поэтому рамка/арт получаются ровно такими же, как в 4:3 (вписаны по высоте),
клики, скроллбары и тултипы работают без отдельных пересчётов (они и так k-схема).

При `HD_K == 1` (4:3) и `InitBillboard`, и `_push` выходят до этой логики —
изменений нет вообще.

## Как проверить

```
powershell -File probe_keyshot.ps1 -W 3840 -H 2160 -F 1 -Tag my169 `
    -Steps "S;Esc,R;x462:659;Esc,E;x378:661"
```

* шаг 2 — R: центральная 4:3-колонка, рамка на всю высоту;
* шаг 3 — help из R (клик по «?» = canvas `462:659`);
* шаг 4 — E: клик по иконке категории (`x142:616`) открывает главу;
* шаг 5 — help из E (клик по «?» = canvas `378:661`).

4:3-регрессия — та же команда с `-W 1920 -H 1440 -F 0 -Strip` и стандартной
последовательностью (`S;Esc,R;Esc,E;Esc,G;Esc,Esc,F1;Esc,Esc,Tab;Tab`): в 4:3 правка
не исполняется.

F1 в игре не диспетчится движком — help-экраны открываются только кликом по «?»
(или горячей клавишей help, если она назначена), это не связано с патчем.

## Историческая справка

Ранее делалась попытка «Q-режим» (экранный квадрат `h x h`, q-трансформ, отдельные
сжатые Q-листы шрифтов, правки трёх ui-модулей). Она отменена и удалена из проекта:
из-за неверной модели размера экраны выходили в `k = 0.75` раза меньше 4:3, а хит-тест
считался k-схемой при q-прямоугольниках → клики мимо. Подробности — `docs/NOTES.md` (файл удалён; содержание распределено по docs/**, указатель docs/INDEX.md),
раздел «R/E/F1: финальное решение».
