# Исследование: масштабирование текста патчем EXE (масштаб при отрисовке + апскейл листов)

Итог: **возможно, один бинарный патч EXE, 3 точки**. Движок UI-текста целиком
скомпилирован в `LETHALDREAMS.EXE` (не в упакованном `lethaldreams.dll`). Масштабный
рычаг найден: адванс глифа (`slot4`) — единственная величина, определяющая ширину
глифа и шаг строки. Патч множит его на коэффициент, вычисленный из разрешения.

## 1. Архитектура (подтверждено реверсом, Ghidra + objdump)

- Движок **в EXE**: таблицы методов Python-классов лежат в данных EXE
  (`Billboard` → `0x50f410`, `Billboard3D` → `0x50f674`, `GameManager`/`SetDisplayMode` →
  `0x50fc08..0x50ffd8`), все реализации — в `.text` (`0x401000..0x4eb000`).
  `lethaldreams.dll` (упакован, `.sforce`) к отрисовке UI-текста не относится;
  `BTexturer.dll` — упаковщик листов. **EXE не упакован, ASLR нет, DEP (NX) не включён.**
- Живая цепочка отрисовки UI-текста (static call-graph):
  `BScene::Render` `FUN_00481990` → `RenderBillboards` `FUN_0047f860` (virtual slot +0x6c)
  → **`Billboard::Render` `FUN_0040b290`** (единственный root-caller текстового рендера,
  читает `billboard+0x294` = шрифт) → **`FUN_0041d560`** (цикл строк) →
  **`FUN_0041d020`** (глифы) → GL-объекты.
  Фrida-счётчики 0 из `SCALING_HANDOFF.md` — артефакт умирающего при attached-сессиях
  процесса; статически путь подтверждён.
- Парсер `.fdf`: `FUN_0041ce40`. Строка `%s %f %f %d` = `char x y adv`:
  `slot0=x (+0x5c)`, `slot1=y (+0x60)`, `slot4=adv (+0x6c)`; pitch (2-е поле header) →
  `font+0x40`; имя листа → `font+0x48`.
- UV-prepare `FUN_0041cc90` (первый вызов d020, флаг `font+0x58=0`): для каждого глифа
  `u0=x/texW`, `u1=(x+adv)/texW`, `v0=y/texH`, `v1=(y+pitch)/texH`. Т.е. **UV нормализуются
  размером листа**: апскейл листа 2× с удвоением всех координат `.fdf` оставляет UV
  неизменными.
- Вершина глифа (`FUN_0040b210`): `(x, y, -1.0f, w, u, v, 0, 0)`; `w = font+0x54`
  (`font+0x1464` копирует `font+0x54` в начале d560) — глобальный масштаб both-осей,
  X-селективный рычаг из него не получается.
- `SetFont(size)` биндинг `FUN_0040bb00`: парсит аргумент и **выбрасывает** size
  (`FUN_0040b490` кладёт только указатель шрифта в `billboard+0x294`) — объясняет
  найденный ранее «нет эффекта от SetFont».

## 2. Рычаг: адванс (`slot4`)

В `FUN_0041d020` (fileoff = VA − 0x400000):

| адрес | bytes | код | роль |
|---|---|---|---|
| `0x41d1b7` | `db 46 10` | `fild qword [esi+0x10]` | загрузка adv → ширина квада X1 = `x+adv` |
| `0x41d1c1` | `fadd [esp+0xec]` | + x | `local_cc = adv + x` |
| `0x41d3fb` | `db 84 24 f0 ...` | `fild [esp+0xf0]` + `fadd [esp+0x14]` | шаг: `x_next = param_4 + local_cc` |

Высота квада = pitch (`font+0x40`), добавка строки = pitch+RowS. Все X-метрики
(`GetTextWidth` `FUN_0041c1f0`, центрирование в d560 case 1/2, hit-test) считают по
`slot4`. **Одна точка патча в парсере распространяется на отрисовку и метрики.**

## 3. Точки патча (рекомендуемый план, file offsets)

Точка 1 — парсер `.fdf`, запись pitch: VA `0x41cedc` (`89 56 40`, `mov [esi+0x40], edx`).
Cave-A: перед записью `edx = round(pitch * ky)`.

Точка 2 — парсер `.fdf`, запись `slot4`: VA `0x41cf52..0x41cf56`
(`89 48 6c 8d 54` → `e9 rel32`+ landed nop-less, возврат в `0x41cf59`).
Cave-B: `adv = round(adv * kx)` в `[esp+0xc]`, затем штатные `mov [eax+0x6c],ecx`,
`mov edx,[esp+0xc]`, возврат в `0x41cf59`.

Точка 3 — `SetDisplayMode` `FUN_00477de0`: VA `0x477df5..0x477dfa`
(`81 ec d0 00 00 00` → `e9 rel32` + `90`); cave-C: после `sub esp,0xd0` читает
`w=[esp+0xe4]`, `h=[esp+0xe8]`, считает
`kx = h*1024 / (w*768*U)`, `ky = 1/U` (U — коэффициент апскейла листа),
пишет в статик; восстанавливает `esp`; возврат в `0x477dfb`.

- Статик `kx/ky/константы`: зона `0x51c000..0x51c140` (VA, `.data`, ~240 нулевых байт
  в файле, raw `0x11c000`). `.data` характеристики `0xc0000040` = RWE — **секция
  исполняема, DEP не включён (DllCharacteristics=0), ASLR нет** → cave исполняется без
  правки заголовков секций.
- Формула: при апскейле листа U=1 (родные листы) `kx = h*1024/(w*768)` = 0.75 для
  3840x2160 и 2560x1440, 1.0 для всех 4:3 (→ побитовая идентичность:
  `round(adv*1.0)=adv`). При U=2 (листы 2×) `kx = k/2 = 0.375`, `ky = 0.5`.

## 4. Схема «апскейл листа + сжатие при отрисовке» (цель пользователя)

1. Офлайн: листы `ld_uncial20`/`ld_uncial12`/`ld_tahoma11`/`ld_numbers15` upscale 2×
   (clean 2x, не интерполяция) → `.btf`; `.fdf` ×2 (`size`×2, `x`×2, `y`×2, `adv`×2) —
   сайдкары `_169` по той же схеме, что `mm_bkg01` (выбор по аспекту в `hd_res.Prepare()`).
2. EXE-патч (3 точки выше) сжимает `adv` и `pitch` при загрузке шрифта:
   `kx=k/U`, `ky=1/U`. Канвас-размер глифа = исходный, UV = исходные, **texel-плотность
   на экране ×2 → текст острее в 4K**. Движок семплирует родный(2×)-лист при smaller-кваде —
   downsampling уходит из текстуры в геометрию.
3. Регрессия 4:3: `kx=ky=1`, листы оригинальные — идентично (проверка md5 снимков).
4. Межстрочный шаг/центрирование: метрикам движка (`GetFontSize=+0x40`,
   `GetTextWidth`=Σslot4) патч сообщает канвас-значения эталона; `hd_scale`
   (`RowS_new = k*(pitch+RowS)-pitch`, `GetRealTextHeight/HD_K`) остаётся рабочей базой,
   `HD_FM` обнулить.

## 5. Ограничения и риски

- **Смена разрешения mid-game**: `.fdf` парсится один раз (звезда старта). `SetDisplayMode`
  пересчитает `kx`, но слоты уже записаны. Варианты: (а) канонический workflow (`hd.cfg`+
  перезапуск) — достаточен; (б) в cave-C добавить обход загруженных шрифтов
  (таблица ресурсов `DAT_0051d530`, менеджер `FUN_0041e8c0 LoadFont`) и перемножить слоты —
  реализуемо, отдельная итерация.
- Округление: `adv*kx` при U=2, k=0.75 = `adv*0.75` → целые с шагом 4 округляются точно,
  `adv=6→4.5` даёт ±1 px (метрики согласованы патчем, визуально незаметно; контроль —
  протокол T=170).
- Console-overlay (`FUN_004134f0`, debug FPS) тоже рисует через d020 — получает тот же
  kx, согласован.
- Точки патча заданы для текущего EXE (патченный набор `exepatch3.py`,
  md5 `45e93d46aad6ceb3dfc17e86d04e4f82`). Новый скрипт — `приватный архив сессий Project/1.7z, entry LethalDreams/exepatch4.py` (исторический скрипт (не в git)), бэкапы по схеме
  `backup_orig/`.
