## Кратко

Написать декомпилятор байткода Python 2.2 (движок Lethal Dreams), который восстанавливает
исходник **со всеми литералами по значениям**, а не по индексам `co_consts`.
Требование приёмки: ни одного `LOAD_CONST` в produced-компиляте, значение которого
отличается от значения в оригинальном `.pyc`.

## Почему это нужно (проверено live, 2026-11-15)

Декомпилят `decompiled_snap/ui/battlemenu.py` испорчен: в списках параметров движка
декомпиллятор печатает **индекс** константы как целое. Пример (оригинал vs декомпилят):

```
Оригинал (dis оригинального игрового `.pyc` — файл установленной игры, в git не входит;
CBattlemenu.__init__):
  LOAD_CONST 750; 0; 244; 50; ui.GUI_TNORMAL; CONST7 ''(строка); 0;
  BUILD_LIST 8: inner = CONST7 ''(строка), CONST8 'ld_uncial12', FONT_H, CONST3 1, CONST2 0, CONST2 0
Декомпилят (decompiled_snap/ui/battlemenu.py, DM_Pane):
  ui.BActionElement([750, 0, 244, 50, ui.GUI_TNORMAL, '', 0, [7, 8, FONT_H, 3, 2, 2]], [], [])
```

Итог: `TextParams[0] = 7` (int), а движок ждёт строку. Живой трейсбек из игры
(`hd_scale._pexc`, лог `config[game.root]/hdlog.txt`):

```
BM-B0EXC 'int' object has no attribute 'find'
  | patches/ui/battlemenu.py:961 self.StatDisplay = ui.BActionElement([30,100,300,300, ui.GUI_TNORMAL, '', 0, [7, 8, FONT_H, 3, 2, 2]], [], [])
  | ./Data/Scripts/ui/ui.py:1169  | patches/hd_scale.py:267  | ./Data/Scripts/ui/ui.py:386
  | ./Data/Scripts/ui/ui_macros.py:123 (RT_ParseText: string.find(text, ...))  | lib/string.py:179
```

Последствие: создание боевого меню обрывается, **весь боевой HUD исчезает**
(проверено снимками `scratch_dir('ld')/p4kbt_overland.png`, `scratch_dir('ld')/p43bt2_overland.png` (снимок прогона съёмки; пересоздаётся скриптами, в git не входит)).

### Почему существующие инструменты не спасают

- `python3 tools/pyc/pycbuild.py fixints ui/battlemenu` → `целые-индексы заменены 0`.
  Причина: выравнивание кодовых объектов **по индексу дерева** (`fixints_text`).
  У декомпилята 124 кодовых объекта, у оригинала 126 (декомпиллятор терял функции),
  поэтому после первого расхождения все потоки токенов расходятся.
- `python3 tools/pyc/pycbuild.py fixlits ui/battlemenu` → `литералов из оригинала 96, подставлено 0`
  (`reconstruct_literals` ловит только простые присваивания `self.X = литерал` / `x['k']=v`;
  списочные литералы параметров движка он не восстанавливает).
- **Паритетный гейт НЕ видит эту порчу**: `pycbuild.signature` сравнивает таблицу
  `co_consts` целиком. Целые 7, 8, 3, 2, 2 совпадают с уже существующими мелкими
  int-константами того же кодового объекта, поэтому `sig=0`, близость 0.9950, и
  запись в `docs/NOTES.md` (файл удалён; содержание распределено по docs/**, указатель docs/INDEX.md) («паритет 0.9950, расхождений sig=0 → патч безопасен») ложна.
  Строковые литералы при этом теряются.
- Уже зафиксировано пользователем в `docs/NOTES.md` (файл удалён; содержание распределено по docs/**, указатель docs/INDEX.md): «правки поверх целых декомпилированных
  модулей ломают игру; декомпилят непригоден как база правок; база правок =
  оригинальные `.pyc` + минимальный собственный модуль».

Рабочий инструмент для восстановления литералов существует только частично:
`tools/pyc/py22_worker.py` режимы `litfix` (выравнивание по индексу), `litfix2` (добавлен:
печатает `CODE side idx имя`, `CONST side idx hexrepr`, `TOK side idx j tok`,
`SLINE idx j line`) — он позволяет выравнивать объекты **по именам**, но готового
декомпиллятора нет.

## Инструментальная база (проверено)

- Интерпретатор движка: `config[py22.interpreter]` (Python 2.2.3),
  `PYTHONPATH="scratch_dir('py223');config[game.root]/Lib"`
  (шум `'import site' failed` — нормальный).
- Магия `.pyc` = `60717` (0xED2D), файл: 8 байт header, дальше marshal кодового объекта.
- `decompiled_manifest.json` — 434 модуля: `{'battlecamera.py': {'md5':…, 'size':…, 'mtime':…,
  'pyc': 'config[game.root]/data/scripts/battlecamera.pyc'}, …}`.
- Оригиналы `.pyc` (чистые, до патчей): `backup_orig/`
  (`ui/battlemenu.pyc`, `ui/olmenu.pyc`, …).
- Парсер байткода проекта: `pyc_scan.py` (`read(buf, 8)` → код+позиция,
  константы/имена/код), `load_opcodes()`; нормализация `pyc_norm.py`
  (`tolerant_ops`, `similarity`), дис-хелперы в `pycbuild.py`
  (`run_worker('dis-pyc'|'dis-py'|'litfix'|'litfix2'|'consts'|'lit'|'vdiff'|'fnames'|'build'|'compile', …)`).
- `HAVE_ARGUMENT` для 2.2 = 90.
- Синтаксис 2.2, который должен уметь emitted-код: `print` statement, `apply(...)`,
  `exec '…'`, `eval(...)`, lambda, классы без `__module__`-присваивания (артефакт
  alpha 2.2a4 — `pyc_norm.tolerant_ops` его допускает), дублирующийся `RETURN_VALUE`
  в конце функции (артефакт диса — уже известный, не трогать).
- Строки в `.pyc` — байты cp1251 (`'\xcd\xe0\xf7\xe0\xf2\xfc'`). В `.py` пишем их как
  ascii repr с \x-эскейпами (как в существующих декомпилятах), файл `.py` — LF, utf-8.

## Что сделать

1. Новый скрипт `decompile_lit.py` (python3, работает через воркер py223 для компиляции
   и дис-а) **или** полноценный собственный декомпиллятор байткода 2.2. Обязательное
   ядро: при эмиссии любой инструкции с операндом `co_consts[arg]` печатать
   **значение** константы (`py2_literal`), никогда индекс. Это покрывает:
   строки, числа, кортежи, списочные литералы (последовательность `LOAD_CONST…BUILD_LIST n`).
2. Проверять результат компиляцией produced-`.py` воркером `build` и **сравнением
   потока токенов с оригиналом**, выровненным по ИМЕНАМ кодовых объектов
   (`difflib.SequenceMatcher` по списку `co_name`, как в режиме `litfix2`).
3. Гейт A (обязательный, по всем 434 модулям): количество `LOAD_CONST`, где значение
   компилята ≠ значения оригинала (в выровненных позициях), = **0**. Отчёт: список
   модулей, где выравнивание даёт «лишние/потерянные» кодовые объекты (декомпиллятор
   теряет функции) — это отдельная ценность: для `ui/battlemenu` известно 126 против 124.
4. Гейт B (для пилотного модуля `ui/battlemenu`): produced `.py` должен содержать
  восстановленные строки, например в `CBattlemenu.__init__`:
   `[750, 0, 244, 50, ui.GUI_TNORMAL, '', 0, ['', 'ld_uncial12', FONT_H, 1, 0, 0]]`
   и 9 мест вида `['', 'ld_uncial12', FONT_H, …]`. Проверка: `grep -c "ld_uncial"
   produced.py (утрачен: покрытия нет ни в git, ни в приватных архивах сессий Project/1-3.7z, 5.7z, 6.7z, 7.7z, original.7z, hd_pack.7z, python_libs.7z)` > 0 (в декомпиляте сейчас 0), и после компиляции `dis` даёт
   `LOAD_CONST 750 … LOAD_CONST ''(7) LOAD_CONST 'ld_uncial12'(8) LOAD_GLOBAL FONT_H
   LOAD_CONST 1(3) LOAD_CONST 0(2) LOAD_CONST 0(2) BUILD_LIST 6 BUILD_LIST 8`.
5. Метрика литералов: число строковых литералов в produced `.py` = число строковых
   констант оригинального `.pyc` (по кодовому объекту). Реализовать как отчётную функцию.

## Куда писать и чего НЕ трогать

- Результаты — в каталог `decompiled_fixed/`
  (`ui/battlemenu.py`, …). **Не** изменять `decompiled_snap/`, `build/`, `patches/`,
  `pyc_norm.py`, `pycbuild.py` (существующие команды должны остаться работоспособными;
  новые режимы добавляй в `tools/pyc/py22_worker.py` аккуратно, без правки существующих).
- В игру (`config[game.root]/data/scripts/`) **ничего не устанавливать**: живая игра
  сейчас содержит наши `.pyc` (патчи `gamescript`, `hd_res`, `hd_scale`, `ui/olmenu`),
  и `pycbuild.py parity <module>` сравнивает с **живым** файлом, а не с оригиналом —
  для сравнения используй `backup_orig/ui/battlemenu.pyc` (пример: `tools/pyc/parity_vs.py` (источник в git; собираемые блобы — в paths.cache_dir('cave'))).
- Игра запускается скриптом `probe_loadshot.ps1`; запускать её для этого задания **не нужно**.
