# ISSUE: движок не грузит `.tex` записи с изменённым размером (2x-апскейл)

Проблема найдена 2026-11-17 на ветке `tex-ground-unpacker`. Цель была: раскодировать
почвенные `.tex` в PNG, сделать Lanczos-3 апскейл 2x, положить результат обратно в
`.map`, снять оверленд и бой. Первые два шага сделаны (см. `docs/TOOLS.md`
«tex-пайплайн», `upscale_tex.py`); **третий шаг не проходит**: игра закрывается при
загрузке карты с апскейленными записями.

## Эксперименты (всё на scratch-дереве `D:/tmp/cygwin/opencode/ld/tex_hook_tree`)

Канонический прогон съёмки: новая игра, снимки окна probe'ом
`tools/archive/probes/probe_loadshot.ps1 3840 2160 1 <Tag> -Mode new -SkipClicks 2
-CharX 349 -CharY 658 -EnterCount 2 -LoadWait 8`.

1. `[P]` Полный `--up2x` (все 44 записи, 1024²→2048² в т.ч.): снимки
   `scratch_dir('ld')/up2xnew_menu.png`, `up2xnew_list.png`, `up2xnew_skip.png`,
   `up2xnew_sel.png` есть; **оверленда нет** — процесс игры завершается сам сразу
   после ENTER x2 (probe печатает `Stop-Process ... NoProcessFoundForGivenId`).
2. `[P]` Ограниченный `--up2x --maxsrc 512`: записи > 512 остаются родными, все
   апскейленные ≤ 1024² (движок грузит 1024² нативно — 9 таких записей в установке).
   Тот же краш: снимки `up2x512_menu/list/skip/sel.png`, оверленда нет.
3. `[P]` Минимальный — одна карта, одна запись: `--map portal_domain.map --up2x
   --maxsrc 512` меняет только `portal_domain_1.tex` (bpp4) с 32² на 64²
   (blob 4096 → 16384). Тот же краш: снимки `pdonly_menu/list/skip/sel.png`,
   оверленда нет. **64² — крошечная запись; движки грузят текстуры больше**
   (`mm_bkg01` = 2048² в ресурсах), значит отказ не из-за «слишком большой текстуры».
4. `[P]` Контроль same-size: все паттерны (круг/полосы/solid, `--alpha
   keep|opaque|zero`) меняют только пиксели при родных w/h — игра грузит и
   отображает корректно (прогоны `taxcircle*`, `texnew*`). В чистом дереве probe
   доходит до оверленда (`scratch_dir('ld')/battleclean_overland.png`).

Вывод: движок принимает `.tex`-запись **только родного размера**; любое изменение
w/h (даже 32²→64²) приводит к закрытию игры на загрузке карты. 2x-ресурсы в `.map`
напрямую не ложатся.

## Проверки целостности контейнера (краш НЕ из-за битого .map)

- `[P]` Патч пересобирает payload и поля контейнера (`plen`,`clen`); перечитанный
  `load_payload` сходится: declared plen == длина payload, zlib распаковывается.
- `[P]` Round-trip в патчере побитовый: перечитанный blob == ожидаемый,
  `blob_len == w*h*bpp` у всех записей после патча.
- `[P]` Лимит шапки 33554432 не превышен (2048²RGBA = 16777216).
- `[P]` В payload карты парная копия `w,h` встречается ровно один раз — в шапке
  записи (поиск u32-пар по payload, `portal_domain.map`: 1024²-пара 1 раз, 32²-пара
  1 раз). Геометрия карты НЕ содержит отдельных копий размеров записей.

## Что известно о шапке записи

`[P]` Поля шапки всех 44 записей: `[0]=w`, `[4]=h`, `[8]=alpha`, `[36]=blob_len`
(размерные), и константы `[12]=[16]=2`, `[20]=[24]=[28]=16777216`, `[32]=119`.
Старшие байты blob_len (`count = blob_len>>16` для ≥ 65536, `>>8` иначе) меняются
при смене размера; каноническое положение count'а в шапке не найдено
(`tools/tex/scan_tex.py`).

## Гипотезы

1. `[?r]` Движок выделяет текстуру по данным, которые знает о записи **до** чтения
   шапки (таблица материалов, кэш карты, размер тайла геометрии) — новый размер
   не совпадает с аллокацией, краш.
2. `[?r]` Движок читает `count` (число 256×256-блоков) из непонятного поля/места и
   по нему собирает blob; при изменённом blob_len count рассинхронизирован.
3. `[?r]` В EXE жёсткий максимум размера текстуры `.tex` — но это не объясняет
   отказ 32²→64² (`mm_bkg01.btf` 2048² живёт в тех же движках).

## Что нужно, чтобы разобраться

- `[P]` REA-разбор кода загрузки `.tex` в движке (ищем обработчик TLV `'w'`,
  чтение w/h/blob_len, аллокацию текстуры; вызов из модулей
  `data/materials/<map>_opaque_N.pyc` → `AddTexture('<map>_<N>.tex')`).
  Точки входа: строка `LDPACKER`, TLV-тип `'w'` (119), имена `.tex` в EXE/DLL.
- `[P]` Понять, где движок хранит ожидаемый размер записи (таблица материалов?
  геометрия карты? имя = ключ, размер из шапки?) — и какие поля надо обновить вместе
  с w/h/blob_len, чтобы апскейл принял.
- `[P]` После разбора — повторить гейт: записи 2x грузятся, оверленд снимается,
  сравнение земля-до/после (`tex_src` vs `tex_up2x`).

## Артефакты и воспроизведение

- Апскейлы: `scratch_dir('ld')/tex_up2x` (44 PNG 2x + MANIFEST).
- Патчер: `python3 tools/tex/patch_map_pattern.py --tree <дерево> --up2x
  <tex_up2x> [--maxsrc N]` / `--restore`.
- Съёмка: probe'ы выше; снимки прогона — `scratch_dir('ld')/ld/*.png`.
- Дерево сейчас: карты восстановлены (`--restore`), игра закрыта.
