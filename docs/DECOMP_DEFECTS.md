# DECOMP_DEFECTS.md — дефекты декомпиляторов базы `decompiled_fixed/`

База восстановлена **decompyle 2.3.2** (`vendor/decompyle`, ставится
`tools/pyc/fetch_decompyle.py`; прогон — `tools/pyc/decompyle_base.py`).
Раздел 1 — что было у прежнего декомпилятора и как это лечили суррогатно;
раздел 2 — что осталось у нового и как это проверяется.

## 1. Принято: замена декомпилятора (2026-11-28)

- Источник — РОДНЫЕ `.pyc` из `original.7z`, не установка (там уже наши патчи).
  Гейт прогона: «ядро опкодов» компилята 2.2.3 против родного `.pyc`
  (`tools/pyc/pyc_bytes.py: core()`); модуль без паритета не пишется.
- decompyle печатает **значение** константы (а не индекс `co_consts`) и
  отдаёт общий хвост `if`/`else` обеим ветвям — классы дефектов 1–3 ниже у него
  отсутствуют, recovery-проходы (`decompile_lit`, `lit_order`, `lit_scan`) не нужны.
- Косметика под прежнюю базу — в прогоне, а не в патчах: склейка соседних
  импортов в одну строку, снятие лишних скобок, схлопывание переносов внутри
  литералов (`merge_imports`, `minimize_parens`, `unwrap_literals` в
  `decompyle_base.py`). Байткод от этого не меняется — гейт тот же.
- `dictionary_rus` (10 561 опкод в одном кодовом объекте) decompyle не берёт
  (spark-парсер: «Stack overflow») — восстанавливает `tools/pyc/litmod.py`,
  0 расхождений опкодов.
- Почему не pycdc: теряет скобки (`ui/ui.CenterRect`) и тела функций
  (`spells/darktwin.StartCast`) — при нулевом паритете по большинству модулей.

## 2. Откуда это видно: прежний стек и его суррогаты

Прежняя база — uncompyle6 3.9.3 поверх `.pyc` игры + два recovery-прохода.
Перечень дефектов сохранён как история и как требования к декомпилятору.

### 1. Индекс `co_consts` вместо литерала (uncompyle6)

- **Симптом:** в списках параметров движка целое вместо строки/кода: `['', 'ld_uncial20', 104, ...]`
  вместо `['', 'ld_uncial20', FONT_H, ...]`; `TextParams[0] = 7` →
  `AttributeError: 'int' object has no attribute 'find'`, создание `CBattlemenu`
  обрывается (живая проверка BHUD).
- **Масштаб:** 33 модуля (`overlandcharacters` 121, `ui/gui_templates` 101,
  `overland_map` 75, `dialogs/*` 11–30, `ui/cursor` 12, `ui/mainmenu` 4, …).
- **Суррогат:** `tools/pyc/lit_order.py` — литералы списков/кортежей из
  оригинального `.pyc` стеком, затем целые позиции отдельным проходом.
- **Паритетный гейт порчу не видел:** индекс int совпадает с int-константой того
  же кодового объекта (`sig=0`).

### 2. Перестановка элементов литерала (потерян порядок)

- **Симптом:** `mainmenu.ShowMainmenu(1, [1, 1, 1, 0, 0, 3])` вместо `[0, 0, 1, 1, 1, 3]`
  → пункты «Выход из игры»/«Настройки» без hover и горячих клавиш (Esc из боя).
- **Причина:** multiset-delta recovery спаривал значения **по количеству без
  порядка**; порядок восстановим только целым литералом из оригинала.

### 3. Общий хвост веток приписан одной ветке

- **Симптом:** после «пропустить ход» ИИ-ход не заканчивается (`CurrentPlayer`
  держится 30+ с вместо цикла `3→4→5→0→1→2`).
- **Причина:** декомпилятор привлёк `bdom.SetInterfaceMode(0)`,
  `bdom.InitializeData()`, `return bdom` только к `else`; `if`-ветка
  заканчивалась голым `return` и возвращала `None`.
- **Суррогат:** правка `decompiled_fixed/ui/battlemenu.py` руками. decompyle
  даёт эту ветку правильно сама: её пересборка побайтово равна родному `.pyc`.

### 4. Лишние локальные переменные

- `co_varnames` компилята содержал имя, которого нет в оригинале
  (`CBattlemenu.UpdateMS`: лишний `dc`). Ловится `tools/pyc/pyc_bytes.py --names`.

### 5. Дублированные `return`

- В хвостах функций декомпилятор печатал `return x` и второй `return`
  — байткод длиннее оригинала, семантика та же. Снимается сверкой
  (`pyc_bytes.core` схлопывает хвост).

### 6. Косметика компилятора (не дефект декомпилятора, мешала сверке)

- `LOAD_GLOBAL __name__` + `STORE_NAME __module__` в телах классов: в родных
  `.pyc` их нет (эмитится с Python 2.3) — сравнение сдвигалось на 2 позиции.
- `CreateBattlemenu`: родной код грузит `LOAD_GLOBAL Battlemenu`, компилят —
  `LOAD_NAME`; `stacksize` модульного кода 10 против 7; `firstlineno` съезжает.
- Альфа-свёртка констант: родные `-0.956`, компилят печатает положительное
  значение + `UNARY_NEGATIVE` (~60 модулей `mentality/ani_*`, `npc_*`).

### 7. Неполные декомпиляты

- `dictionary_rus` — только заголовок uncompyle6 (237 байт), тело не
  декомпиллировалось; восстановлено 0 модулей.

### 8. Артефакты текста исходника

- Хвостовые комментарии `# global … ## Warning: Unused global`, дубли `return`
  на пустых ветках, `exec 'import ' + name` / `eval(name)` вместо `__import__`,
  `if (x):` со скобками. Семантику не ломают.

## 3. Что осталось у decompyle 2.3.2

| модуль | объект | расхождение |
|---|---|---|
| `mentality/std_brains` | `__init__` | цель `JUMP_IF_FALSE` на 1 опкод |
| `overland_map` | `CreateBattleUnit` (2 объекта) | цель `JUMP_IF_FALSE` на 1 опкод |
| `tutorial_lesson3` | `Initialize` | цель `JUMP_IF_FALSE` на 3 опкода |
| `os` | `_execvpe` | цель `JUMP_FORWARD` на 1 опкод |

Это форма ветки в исходнике (лишняя/недостающая пара `POP_TOP`/`JUMP`), не
семантика: значения, порядок констант и вызовы совпадают. Остальные 430 модулей
совпадают побитово (включая `dictionary_rus` после `litmod`).

## 4. Инструменты проверки (канонические)

| инструмент | что проверяет | запуск |
|---|---|---|
| `tools/pyc/decompyle_base.py` | прогон декомпилятора + гейт «ядро опкодов»; `--jobs N`, `--only`, `--resume`, `--normalize-only`, `--write` | `python3 tools/pyc/decompyle_base.py --jobs 8` |
| `tools/pyc/check_patches.py` | патч ложится на базу и даёт тот же `.pyc` | `python3 tools/pyc/check_patches.py [--base DIR]` |
| `tools/pyc/port_patch.py` | перенос правок на новую базу по выравниванию строк (+ гейт байткодом) | `python3 tools/pyc/port_patch.py --all --base <dir>` |
| `tools/pyc/pyc_bytes.py` | сверка двух `.pyc` на уровне маршалла (`--core`, `--names`, `--fields`) | `python3 tools/pyc/pyc_bytes.py <orig.pyc> <mine.pyc> --core` |
| `tools/pyc/litmod.py` | восстановление «плоского литерального» модуля (fallback) | вызывается прогоном |

## 5. Критерии проверки декомпилята

1. **Статика:** `decompyle_base.py` — 0 расхождений ядра на модуль (кроме
   перечисленных 4 объектов), `pyc_bytes --names` — совпадающие
   `co_names`/`co_varnames`/`co_consts`.
2. **Патчи:** `check_patches.py` rc 0 — каждый патч применяется к базе и даёт
   байткод установленной сборки.
3. **Живой прогон (критерий хода компьютера):** загрузка сейва → `T` → `Enter`;
   детектор должен дать смену `CurrentPlayer` ≥ 2 раза и приход к `own=1`.
4. **Детектор:** `TURN` пишется только внутри `Invalidate(CURRENT_PLAYER_CHANGED)` —
   во время ИИ-хода UI не обновляется, смен в логе нет; нужен опрос `CurrentPlayer`
   по таймеру (`olmT_D`: `gamemodule.SetTimer(0, StatTick)`, лог раз в 45 вызовов).
   Опрос каждый кадр душит игровой цикл. Логи прогонов затирать нельзя:
   `perform_action_in_game.ps1` пишет `hdlog.txt` в корень дерева.

## 6. Требования к декомпилятору базы

1. Вход: magic `0xED2D` (Python 2.2.3), marshal v1; все 434 модуля, включая
   `dictionary_rus` (или fallback на плоские литеральные модули).
2. Литералы — значения, никогда индекс `co_consts`; порядок элементов
   списков/кортежей = порядок `LOAD_CONST` перед `BUILD_LIST`/`BUILD_TUPLE`.
3. Структура: общие хвосты `if`/`else`/`while` (слияние ветвей), точные
   `return x`, только те локалы, что есть в `co_varnames`.
4. Поддержка `exec`-стейтментов и `eval`-загрузок карт (`exec 'import ' + name`),
   без замен на `__import__`.
5. Результат должен проходить раздел 5 (статика + патчи + живой прогон).
