# DECOMP_DEFECTS.md — дефекты декомпиллятора и что пришлось фиксить

Каталог всех дефектов, найденных в декомпилятах базы `decompiled_fixed/` (источник —
uncompyle6 3.9.3 над `.pyc` игры, magic `0xED2D` = Python 2.3, marshal v1), и способов их
исправления. Цель: фиксированный список требований к декомпиллятору при поиске замены.

## Классы дефектов

### 1. Индекс `co_consts` вместо литерала

- **Симптом:** в списках параметров движка целое вместо строки/кода: `['', 'ld_uncial20', 104, ...]`
  вместо `['', 'ld_uncial20', FONT_H, ...]`; `TextParams[0] = 7` → `AttributeError: 'int' object
  has no attribute 'find'`, создание `CBattlemenu` обрывается (живая проверка BHUD).
- **Масштаб (позиционный скан 434 модулей, снята альфа-свёртка):** 33 модуля —
  `overlandcharacters` 121, `ui/gui_templates` 101, `overland_map` 75, `dialogs/*` 11–30
  (21 модуль), `ui/cursor` 12, `ui/mainmenu` 4, `ui/bgui`/`ui/enmenu`/`ui/newgamemenu`/`ui/olmenu`
  по 2.
- **Паритетный гейт (`pycbuild`, tolerant) порчу не видит:** индекс int совпадает с int-константой
  того же кодового объекта, `sig=0`.
- **Фикс:** `tools/pyc/lit_order.py` — литералы списков/кортежей берутся из оригинального `.pyc`
  стеком (`LOAD_CONST…` + `BUILD_LIST/BUILD_TUPLE`, режим `purelit` воркера) и заменяются в
  исходнике целым литералом; целочисленные позиции — отдельным проходом после.
  После `lit_order --all` по базе: диалоги (21 модуль), `ui/mainmenu`, `ui/olmenu`,
  `ui/newgamemenu`, `ui/enmenu`, `ui/bgui`, `mentality/*`, `goscripts/*` — 0 расхождений;
  остаток: `overlandcharacters` 125, `ui/gui_templates` 111, `overland_map` 52, `ui/cursor` 8.
  Это int-литералы вне скобочных литералов (аргументы вызовов), где целочисленный проход
  не разрешает позицию; нужен проход, восстанавливающий литералы по всей statement-регионах
  стеком, а не только списки.

### 2. Перестановка элементов литерала (порядок теряется)

- **Симптом:** `mainmenu.ShowMainmenu(1, [1, 1, 1, 0, 0, 3])` вместо
  `[0, 0, 1, 1, 1, 3]` → `Active[3]`/`Active[4]` = 0, пункты «Выход из игры»/«Настройки» без
  hover и горячих клавиш (Esc из боя).
- **Важно:** uncompyle6 порядок НЕ ломает. Свежий запуск на родном `.pyc` даёт
  `mainmenu.ShowMainmenu(1, [1, 1, 2, 2, 2, 3])`, пул констант `BackToMainMenu` = `[None, 0, 1, 3]`,
  то есть индексы напечатаны в байткодном порядке; отображение индекс→значение даёт оригинальный
  `[0, 0, 1, 1, 1, 3]`.
- **Порядок терял наш recovery:** стратегия multiset-delta (`tools/pyc/decompile_lit.py`,
  `docs/PIPELINE.md` стр. 147) спаривает лишние/недостающие значения **по количеству без порядка**;
  при повторяющихся int построчная замена «первого неиспользованного вхождения» целого
  (str.find слева направо) попадает не в тот слот, в т.ч. в аргумент вызова
  (`ShowMainmenu(1,` съедается заменой `1 -> 0`).
- **Фикс:** только замена целым литералом из оригинала (см. класс 1); по одному целому порядок
  восстановить принципиально невозможно.

### 3. Структурная склейка: общий хвост веток приписан одной ветке

- **Симптом:** после «пропустить ход» ИИ-ход не заканчивается: опрос `CurrentPlayer` держит
  `cur=3` 30+ с (родный `.pyc` — полный цикл `3→4→5→0→1→2 own=1`). Лог-пробка внутри модуля:
  вход в `CreateBattlemenu` есть, `MapScript.Initialize(...)` вернулся, до инициализации домена не доходит.
- **Причина:** в родном байткоде после `bdom = MapScript.Initialize([mini_domain, attackers])`
  (`if`-ветка, `DomainType != OL_RANDOM_TYPE`) `JUMP_FORWARD` ведёт в **общий хвост**
  `bdom.SetInterfaceMode(0)`, `bdom.InitializeData()`, `return bdom`. Декомпиллятор привлёк эти три
  строки только к `else`-ветке, `if`-ветка заканчивается голым `return` → боевой домен создаётся
  без инициализации и возвращает `None`, ИИ-ход встаёт.
- **Фикс:** правка `decompiled_fixed/ui/battlemenu.py` — `SetInterfaceMode(0)`, `InitializeData()`,
  `return bdom` вынесены после `if`/`else`. Проверено живым прогоном: ход проходит.
- **Требование к декомпиллятору:** восстанавливать слияние веток (общие хвосты `if`/`else`,
  `while`), а не только блоки исходника; этот дефект не виден ни в литеральном скане,
  ни в паритетном гейте.

### 4. Лишние локальные переменные

- **Симптом:** `co_varnames` компилята содержит имя, которого нет в оригинале:
  `CBattlemenu.UpdateMS` — `[self, type, char, outside, rt, mscnt, dc, vs, key, bk, mskeys, icon, box]`
  против родных `[self, type, char, outside, rt, mscnt, vs, key, bk, mskeys, icon, box]`.
- **Фикс:** ловится `tools/pyc/pyc_bytes.py --names`; правка исходника (удалить присваивание).

### 5. Дублированные `return`

- **Симптом:** в хвостах функций декомпиллятор печатает `return x` и второй `return`
  (`LOAD_CONST None; RETURN_VALUE`) — в компиляте лишние хвостовые пары; семантика не меняется,
  байткод длиннее оригинала.
- **Фикс:** снимается при сверке (`pyc_bytes.core` схлопывает повтор хвоста); правка не требуется.

### 6. Косметика компилятора (не дефект декомпиллятора, мешает сверке)

- `LOAD_GLOBAL __name__` + `STORE_NAME __module__` в телах классов: в родных `.pyc` их нет
  (эмитится с Python 2.3), наш воркер эмитит → `co_names` классов сдвигается на 2 и все
  позиционные сравнения съезжают; снятие обязательно перед сравнением (`lit_scan`, `pyc_bytes`).
- В функции `CreateBattlemenu` родной код грузит имя глобально (`LOAD_GLOBAL Battlemenu`), компилят —
  `LOAD_NAME Battlemenu` (единственная оставшаяся осмысловая разница после всех фиксов).
- `stacksize` модульного кода 10 (родной) против 7; `firstlineno` съезжает (база правок короче оригинала).
- Альфа-свёртка констант: родные константыnegative (`-0.956`), компилят печатает положительное
  значение + `UNARY_NEGATIVE`; ~60 модулей `mentality/ani_*`, `npc_*` дают пары вида
  `(-0.956, 0.956)` — это шум сравнения, не порча; фильтр снят в `lit_order`.

### 7. Неполные декомпиляты

- `dictionary_rus` — в базе только заголовок uncompyle6 (237 байт), тело не декомпиллируется;
  восстановлен 0 модулей (`docs/PIPELINE.md`).

### 8. Артефакты текста исходника

- Хвостовые комментарии вида `# global StaticFGlobalTT ## Warning: Unused global`,
  дубли `return` на пустых ветках, `exec 'import ' + name` / `eval(name)` вместо `__import__`.
  Семантику не ломают; при пересборке исходника сохраняются как есть.

## Инструменты проверки (канонические)

| инструмент | что проверяет | запуск |
|---|---|---|
| `tools/pyc/lit_scan.py` | позиционное сравнение нормализованных операций компилята с родным `.pyc`; шум `__name__`/`__module__` снимается; int-индекс `co_consts` = «литералов-индексов» | `python3 tools/pyc/lit_scan.py <orig_scripts_dir> [module]` |
| `tools/pyc/lit_order.py` | восстановление литералов: целые списки/кортежи из оригинала + позиционные целые; режим `--scan` — triage без записи, `--all` — проход по базе | `python3 tools/pyc/lit_order.py ui/battlemenu` / `--scan <workdir>` / `--all` |
| `tools/pyc/pyc_bytes.py` | сверка двух `.pyc` на уровне маршалла: побайтовый `co_code`, снятие `SET_LINENO`, снятие `__module__`-пар, схлопывание хвостов, прыжки = индексы опкодов; режимы `--all`, `--fields`, `--names`, `--core` | `python3 tools/pyc/pyc_bytes.py <orig.pyc> <mine.pyc> --core` |
| воркер `purelit` | чистые литеральные списки/кортежи оригинала: `PURE <codeidx> <tokidx> <hex>` | `vendor/py223/python.exe tools/pyc/py22_worker.py purelit <orig.pyc>` |

## Критерии проверки декомпиллята

1. **Статика:** `lit_order --scan` = 0 позиционных расхождений; `pyc_bytes --core` = 0 расхождений
   опкодов (косметика снята), `--names` = совпадающие `co_names`/`co_varnames`/`co_consts`.
2. **Живой прогон (критерий хода компьютера):** загрузка сейва → `T` → `Enter`; детектор должен
   дать смену `CurrentPlayer` ≥ 2 раза и приход к `own=1`.
3. **Детектор:** `TURN` пишется только внутри `Invalidate(CURRENT_PLAYER_CHANGED)` — во время ИИ-хода
   UI не обновляется, смен в логе нет; нужен опрос `CurrentPlayer` по таймеру (`olmT_D`:
   `gamemodule.SetTimer(0, StatTick)`, лог раз в 45 вызовов). Опрос каждый кадр душит игровой цикл.
   Логи прогонов затирать нельзя: `perform_action_in_game.ps1` пишет `hdlog.txt` в корень дерева и
   затирает его при старте следующего прогона — снимать лог сразу после гашения игры.

## Требования к заменяющему декомпиллятору

1. Вход: magic `0xED2D` (Python 2.3), marshal v1; все 434 модуля, включая `dictionary_rus`.
2. Литералы — значения, никогда индекс `co_consts`; порядок элементов списков/кортежей = порядок
   `LOAD_CONST` перед `BUILD_LIST`/`BUILD_TUPLE`.
3. Структура: общие хвосты `if`/`else`/`while` (слияние веток), точные `return x` без дублей,
   только те локалы, что есть в `co_varnames`.
4. Поддержка `exec`-стейтментов и `eval`-загрузок карт (`exec 'import ' + name`), без замен на
   `__import__`.
5. Результат должен проходить проверки раздела «Критерии»: статика `pyc_bytes --core` = 0 и живой
   прогон хода.
