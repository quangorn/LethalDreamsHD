# HANDOFF_mob_occupancy.md — занятость мобов и «застревание мобов друг в друге»

Задача: эксперимент — разрешить mob'ам занимать одну клетку и учитывать это в pathfinding.
Съёмка живого гейта: `tools/probes/battle_169.ps1 -AfterWavesWait 20` (много мобов);
сборка `.pyd`: `python3 tools/ldhook/build.py`.

## Установленное [P]

- Занятость — **per-unit**: BattleAI map1 (`self+0x68`, ключ = pos-указатель),
  map2 (`self+0x74`, ключ = `(Y<<16)|X`). Регистрация `0x45dd00` — писатели:
  grid_recompute P7 (`recompute.cpp`), B10 (`move.cpp`, прибытие), dd70 ветка 1 (`target.cpp`).
  Писателей от чужих юнитов нет — cross-unit блокировки в pathfinding-слоях нет.
- `tree_lookup(world+0x104, key)` (0x449160) — **статичная таблица рельефа**: пишут только
  конструктор 0x44b990 (посев ключей 0..4 → статусы 1,2,0,0,1), копия 0x44b790, парсер
  0x44a800 (пары «key status» из строки конфигурации карты). Инсерт 0x449c00 других каллеров
  не имеет —
  в бою дерево не меняется. Ключ absent → lower_bound = header → статус 1 (проходимо).
- dd70 (`s6_ai_update`, `target.cpp`): ветка 1 при занятости клетки в map2 **переиспользует**
  PathState (`nbr = node->value`), а не блокирует; регистрация только в ветке 1.
  cb40 (`s6_path_search_body`, `path.cpp`): клетка в map2 пропускается радиальным сканом.
- Физическая коллизия юнитов — в движковом коде перемещения (не портирован).
  Кандидаты на разбор: функции 0x4a4830, 0x41acb0 (xrefs константы 10.0f),
  область 0x492500 (xref 0.05f, вне Ghidra-функций).

## Экспериментальные рычаги (env `LDHOOK_*`, дефолт off)

- Гейт cb40 `(void*)LS(0x44) == self->occ_head` — `path.cpp` ~673: клетки своей map2
  пропускаются при радиальном расширении.
- Переиспользование dd70 `nbr = node->value` — `target.cpp` ~2453.
