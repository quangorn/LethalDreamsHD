# PLAN_BATTLE_AI_CPP.md — порт боевой логики и поиска пути в C++ модуль

## Цель

В `ldhook.pyd` должна быть читаемая реализация боевой логики и поиска пути по слоям: `FUN_0044bdd0` (тик боевого AI) → `FUN_0045eee0` (движение/выбор точки) → `FUN_0045e0a0` (поиск цели) → `FUN_0045dd70`/`FUN_0045cb40` (pathfinding). Код модуля — источник истины об алгоритме: имена структур, полей и функций отражают смысл, а не адреса; конечный артефакт понимания — `docs/OBSERVATIONS_BATTLE_AI.md` (Фаза 6) плюс сам C++.
Оптимизация производительности **не цель**; обязательное условие — эквивалентность поведения оригиналу (fidelity-first).

## Границы порта

**Портируется** — всё, что принимает решения: выбор цели, обновление метрик и фронта, стоимость и обход пути, состояние боевого AI, таймауты, учёт занятости клеток. **Не портируется**, вызывается нативно через `native::…`: GUI/HUD/анимация/отрисовка, строки, логирование движка; `0x442570` (состояние игры); аллокатор `0x47abc0` и вставки в родные `std::map` (`0x45d2e0`, `0x45d810`, `0x45dd00`); загрузка ассетов.
Правило классификации: функция портируется, если она (а) меняет выбор цели, (б) считает/меняет стоимость пути, (в) меняет состояние боевого AI; спорные — п. 1.4, вердикт в `docs/OBSERVATIONS_BATTLE_AI.md`. RB-вставка в `std::map` **не портируется**; порт `0x434bc0` (lower_bound) и `0x47f800` (next) остаётся — он сверен и не аллоцирует.

## Инварианты

1. Игра только для чтения; установка — `exepatch12`, эксперименты — baseline scratch, запись в установку — только явным `--install`.
2. `/fp:precise` обязателен; последовательности x87 переносятся 1:1 (см. 1.6).
3. Все игровые адреса — через `native::fn(VA)` (база модуля + смещение от 0x400000).
4. Дизасм-гейт: ни одна функция не портируется без строки дизасма в артефакте разведки (Фаза 1).
5. Один детур на функцию; портированный слой вызывает порты напрямую, нативные обёртки — только листья.
6. Каждый пункт плана = отдельный коммит (≤2 строки) + обновление статуса здесь.

## Исполнение

Оркестратор (текущий агент) запускает **последовательных** сабагентов по одному пункту; параллельные запуски запрещены. Всё, кроме среднего и сложного — `strata/q3.8-fn#medium`; ревью любого пункта — `strata/q3.8-fn#high`; средние и сложные — `openrouter/particle-ai/particle-1:free#high` (обрыв → `continue` той же сессией до 10 раз, после 10-й неудачи — эскалация к человеку; 5 ошибок подряд в живой сессии particle → `openrouter/baidu/ernie-5.5-flash-preview:free#high`). Замер контекста сессии (`<scratch>/ctx.py`) — только при отправке нового задания: при ≥256k задание не ставится, открывается новая сессия.
При исчерпании суточных лимитов средние и сложные идут на `openrouter/@preset/ds-flash-41-cheapest#low`; перевод живой сессии — сменой модели через API opencode (`opencode api post /api/session/<ses>/model`), не новой сессией. Простая рутина (разведка по листингу, таблицы, ABI-сверки) — strata; коммит и финальная правка docs — оркестратор. Неразрешённая семантика (callee, структуры, ABI) — сначала REA (decompile/xrefs), затем листинг; догадки по asm запрещены.
Пункт передаётся с входами, выходом и гейтом; без пройденного гейта следующий пункт не стартует. Исследовательские пункты пишут артефакт в `<scratch>/re/…`, в docs попадает только принятое решение.

### Конвейер пункта

1. **Исполнитель** — реализует пункт по дизасму. 2. **Рецензент** (отдельный сабагент) — сверяет дифф с планом и дизасмом: fidelity, ABI, аллокатор, рекурсия, гонки, читаемость имён; вердикт pass/minor/major/critical, major/critical → отдельный исполнитель правит и снова рецензия, minor не блокирует.
3. **Тестировщик** (отдельный сабагент; только для рабочих пунктов) — прогон Боевого гейта; провал → до 3 попыток исправления, после 3-го — эскалация на человека (шаг, дифф, лог, снимок). 4. **Оркестратор** — коммит и обновление статуса здесь и в `docs/STATE.md`.

### Боевой гейт (снимок саммонов)

`tools/probes/battle_169.ps1` (обёртка `perform_action_in_game.ps1`) на установке (`config[game.root]`, `3840x2160`; A/B на scratch — `LDHOOK_LOG=1`): вход в бой по фиксированным шагам → 3 волны призыва (`-Waves 3`) → снимок через 1 с после 3-й волны → игра гасится. Критерий: рядом с персонажем **≥2 призванных саммона** и отсутствие визуальных поломок; точка спавна случайна (`whrandom.randint` в `InitializeData`), дистанция до ближайшего врага случайна — снимки между прогонами попиксельно не сравниваются. Эталон процедуры — `scratch_dir('battle_baseline')/baseline_summons.png`.

## Фаза 1 — разведка (REA, кода не пишем)

Выход: `<scratch>/re/battle_ai_disasm4.md` (1.3b) и `battle_ai_disasm6_structure.md` (1.3a); для каждой функции — VA, размер, ABI (`RET n`, регистры), вызывающие, callees, поля структур, ветвления. 1.0–1.5: раскладка `BattleAI` (снимает противоречие `+0x6c`/`+0x68`), группа `e0a0`, тело `45eee0` (call sites `0x45f264`/`0x45f368`, хвост `0x45f3a5`), карта `44bdd0`, инвентарь нативных листьев с вердиктом «порт/нативно», стабильность VA и источник времени.

**Решение 1.6.** Control word игры — PC=53 (double) везде: все 32 sites `fldcw` — только CRT-math, `_controlfp` не импортируется, поэтому plain double в MSVC `/fp:precise` бит-эквивалентен comparison-гейтам. Правила ветвлений: JP(0x5) ⟺ NOT(a<b); JNZ(0x41) ⟺ NOT(a>b); JP(0x44) ⟺ (a≠b, unordered = «не равно»). Границы `45cb40` — целочисленные сравнения; `45c8c0` — asm-мост для FPTAN; x87-гейты внутри `44bdd0` — dual. Грабля: `docs/PITFALLS.md`.

**Решение 1.7.** Сравниваемые поля trace — 29 в фиксированном порядке (`tick, unit, code, u170, al, out, c1..i1, fx, fy, lx, ly, c2..i2, g, h10k, cost, trk, bd2, s1, s2, vis, m0..m2`); `us`/`ai` пишутся, не сравниваются. Trace-строка — одна на вызов `44bdd0`, пишется на эпилоге `0x44d074`; хуки и поля — `battle/trace.cpp`. A/B: один `.pyd`, один сейв, одни `-Steps`/`-W -H -F`; пиннинг RNG (`whrandom.seed` + env `LDHOOK_SEED`); сравнивается хвост после контролируемого события. Метод без случайности — офлайн capture/replay (`LDHOOK_BATTLE_CAPTURE=<path>` JSONL).
Diff: `tools/probes/trace_diff.py` (rc 0 — нет дивергенций и хвост достаточен, rc 1 — дивергенция, rc 2 — файл не читается, rc 3 — строк меньше). Гейты Фаз 3–5 — офлайн per-call replay rc 0 (решение 3.7), живой A/B — санитарный.

Гейт: артефакты содержат строку дизасма для каждой функции Фаз 2–5; 1.6 и 1.7 закрыты решением.

## Фаза 9 — поведение (лаги, «стоят на месте», агро)
